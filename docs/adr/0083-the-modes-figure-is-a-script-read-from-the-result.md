# モードごとの結合の図は、結果ファイルのモード表を読む作図スクリプトで描く

- 日付: 2026-09-29
- 状態: 受理

計算に使った結合を目で確かめる手段がなかった。スペクトルの形を読むには、どの振動数のモードが
どれだけ強く結合しているかを並べて見たいが、それは入力ファイルか実効設定の数字を読むしか
なかった。

**`fcenvelope script --modes RESULT.json -o PLOT.py` で、結果ファイルの `conditions.modes` を
描く作図スクリプトを書き出す。横軸はモードの振動数 ω、縦軸は既定で g。** モード 1 つに棒を
1 本、底辺 0 で立てる。線の図（`lines.py`）と同じ作りの雛形 `templates/modes.py` を持ち、
ライブラリ側には `plot_modes(system)` を置く。

## 決まりごと

- 読むのは結果ファイルである。エンベロープと線のどちらの結果も、計算条件として同じモード表を
  正準形（ω [cm⁻¹], S）で持つ（ADR-0080）ので、種類を問わない。生成ヘッダの `KIND` は
  渡した結果の種類になる。
- 縦軸はスクリプト先頭の `Y` で `"g"` と `"S"` を選ぶ。g は √S として描くので常に正である。
  結果ファイルは S しか持たず（ADR-0003）、g の符号は物理的に意味を持たない。
- 横軸のラベルは ω と書く。振動数の記号は理論の文書（`docs/theory/`）に合わせてリポジトリ全体で
  ω に統一した（以前は ε と書いていた箇所があった）。
- 横軸は 0 から始める。単位は他の図と同じく `X_UNIT` / `X_SCALE` で表示だけ換算する（ADR-0062）。
- `run` / `lines` はこのスクリプトを自動では書かない。欲しいときに `script --modes` で作る。
- `--modes` は結果を 1 つだけ取る。2 つ渡すと使用法エラーである。

## 理由

**入力ファイルではなく結果ファイルを読む。** 作図スクリプトは `json` と `matplotlib` だけで
動く（ADR-0058）。入力ファイルを読むには TOML、CSV の参照、流儀と単位の換算が要り、それを
スクリプトに写すと `inputs.py` の二重実装になる。結果ファイルのモード表はそれらを消費し終えた
正準形なので、√ を取るだけで g になる。しかも「その計算が実際に使った値」であり、図と
スペクトルの対応が崩れない。

**縦軸の既定は g。** 入力の既定の流儀が g で（`DEFAULT_COUPLING_CONVENTION`）、利用者が
書き慣れているのも g である。S は同じスクリプトの 1 行で切り替えられる。

**自動では書かない。** `run` / `lines` のたびに 2 本目のスクリプトが増えると、掃引のときに
散らかる。モード表は計算条件を振っても変わらないので、1 度描けば足りることが多い。

## 検討した選択肢

- **`run` / `lines` で既定で書く**: 上の理由で退けた。
- **入力ファイルを直接読む副命令（`fcenvelope modes INPUT.toml`）**: 計算を走らせずに見られる
  利点はあるが、スクリプトが入力の読み方を二重に持つことになる。`fcenvelope lines` は軽いので、
  結果を 1 つ作ってから描けば足りる。
- **`plotting.DRAWERS` / `emit.TEMPLATES` に載せる**: あの表は「結果の種類 → 描き方」であり、
  モード図は種類を問わない。重ね描きと同じく表の外に名前で置く（ADR-0049）。
