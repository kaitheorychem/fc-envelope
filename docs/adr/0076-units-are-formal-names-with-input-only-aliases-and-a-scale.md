# 単位は正式名で持ち、入力ファイルでだけ別名と倍率を受け付ける

- 日付: 2026-09-24
- 状態: 受理（ADR-0054 の単位の表に正式名・別名・倍率の区別を足す。ADR-0065 の実効設定に
  出る単位の字面を正式形にそろえる。倍率の書き方と正式形の形は ADR-0078 が置き換える）

振電相互作用定数 V を出すプログラムは、単位を `a.u.` とだけ書き、しかも値を
`10^-4 a.u.` 単位で出す（ADR-0077）。どちらも入力でそのまま受けられると便利だが、
`a.u.` はそれだけでは次元が読めない。V については質量の単位（m_e か amu か）が落ちて
おり、取り違えると S が約 1823 倍ずれる。そこで単位の文字列を次の 3 つに分ける。

| 区別 | 意味 | 現れる場所 |
|---|---|---|
| **正式名** | 名前だけで次元が読める識別子。`cm^-1`、`hartree`、`hartree/(bohr*sqrt(m_e))` など | プログラム内、実効設定、誤りの報告 |
| **別名** | 入力ファイルでだけ使える慣習的な書き方。**どの欄に書かれたか**で正式名が決まる | 入力ファイルだけ |
| **倍率** | 単位の前に置く正の数。値全体をその数倍して読む | 入力ファイルと実効設定 |

正式名・別名・倍率から作られる、プログラムが保持する単位の文字列を**正式形**と呼ぶ。
別名を正式名に置き換え、倍率は書かれた字面のまま残したものである。

## 別名

別名は**単位の種類**ごとに表を持つ。単位の種類とは、その欄の値がどの次元の量かの区別で、
今は次の 2 つである。

| 単位の種類 | 使う欄 | 正式名 | 別名 |
|---|---|---|---|
| エネルギー | `frequency_unit` / `broadening.unit` / `grid.unit` / これらが既定になる値に添えた単位 / 流儀 `lambda` の `coupling_unit` と coupling に添えた単位 | `ENERGY_UNITS` の 6 つ | `a.u.` → `hartree` |
| 振電相互作用定数 | 流儀 `vcc` の `coupling_unit` と coupling に添えた単位 | `hartree/(bohr*sqrt(m_e))`（ADR-0077） | `a.u.` → `hartree/(bohr*sqrt(m_e))` |

同じ `a.u.` でも、エネルギーの欄なら `hartree`、V の欄なら `hartree/(bohr*sqrt(m_e))` に
なる。coupling の欄の種類は流儀が決める（ADR-0033）。無次元の流儀には単位の種類がなく、
単位を添えれば今までどおり誤りになる。

別名は表に 1 行足せば増やせる。今回足すのは `a.u.` だけとする。`cm-1` や `1/cm` のような
表記の揺れも同じ表に足せるが、必要になってから足す。

## 倍率

単位の文字列の先頭に数を置き、1 つ以上の空白で区切る。

```toml
[broadening]
sigma = [18.6, "10^-3 eV"]          # meV で書く

[[modes]]
frequency = 500.0
coupling = [-0.3, "10^-4 a.u."]     # 相手プログラムの出力をそのまま写す
```

書き方の規則は次のとおり。

- 前後の空白を除いてから空白で区切り、1 語なら名前、2 語なら倍率と名前とする。3 語以上は
  誤りである。
- 倍率は正規表現 `[+]?(\d+(\.\d*)?|\.\d+)([eE][+-]?\d+)?`（小数、指数表記）または
  `10\^[+-]?\d+`（10 の整数乗）に全体が一致する必要がある。一致しない、または値が 0 の
  ときは誤りとする。負の倍率は正規表現の時点で弾かれる。
- 名前の大文字・小文字は区別する（今までどおり）。
- 倍率を空白なしで名前に続けた `1e-4a.u.` は、名前として解釈されて未知の単位になる。
  誤りの報告には受け付ける書き方（`"<name>"` または `"<scale> <name>"`）を添える。

倍率は単位の種類に依存しない。どの単位の欄にも書ける。

## 正式形と書き出し

入力の検証を通った後、`FCEnvelopeInput` とその中のブロックが持つ単位の文字列は**常に
正式形**である。正式形は、倍率があれば `"<倍率の字面> <正式名>"`（間の空白は 1 つ）、
なければ `"<正式名>"` とする。倍率の字面は正規化しない。`10^-4` は `10^-4` のまま、
`1e-4` は `1e-4` のまま残るので、実効設定と手元の入力ファイルの diff が読みやすい。

正式形を読み直すと同じ正式形になる（冪等）。CLI の上書きは実効設定と同じ辞書を作り直して
検証し直すので（ADR-0064）、この性質が要る。

- **実効設定（`*_config.json`）**: 正式形で書かれる。ADR-0065 の「入力ファイルと同じ
  単位で書く」は保たれる。変わるのは同じ単位の**字面**だけで、量としては同じ値なので
  そのまま入力に戻せば同じ計算が再現できる。
- **結果ファイル**: 入力エコーは正準形（cm⁻¹、`huang_rhys`）なので（ADR-0010）、別名も
  倍率も現れない。変更はない。
- **作図スクリプト**: `X_UNIT` は軸の見出しの文字列で、入力ファイルではない（ADR-0062）。
  別名も倍率も扱わない。

## 検討した選択肢

**`a.u.` を正式名にする**: 採らない。質量の単位が落ちるという、この ADR の発端になった
問題がそのまま残る。

**別名を受け付けない**: 相手プログラムの出力に `a.u.` と書かれていれば、利用者はまず
そう書く。正式名しか受け付けないと、毎回の書き換えで取り違える機会を増やすだけである。
別名から正式名への置き換えを入力の境界で 1 回だけ行い、それより内側と書き出しには正式名
だけが現れるようにすれば、便利さと曖昧さのなさの両方が取れる。

**倍率を正規化して書き出す（`10^-4` を `0.0001` にする）**: 読み返したときに入力
ファイルと字面が変わるだけで得るものがない。

**倍率を値の側に書かせる（`coupling = -0.3e-4`）**: 相手の出力をそのまま写せない。
倍率は相手プログラムの**単位の表示**に付いているものなので、単位の側に置くのが素直である。

## 帰結

単位の文字列はすべて入力の境界で正式形へ置き換わり、換算係数は倍率を掛けたものになる。
単位を書いていない入力ファイルも、正式名だけで書いた入力ファイルも、これまでと同じ意味で
読める。上位互換の追加なので、`schema_version` は 3 に据え置く。

### `units.py`

- **単位の種類** `UnitKind` を足す（frozen dataclass）。持つものは次の 3 つ。
  - `name`: 誤りの報告に使う名前（`"energy"` / `"vibronic coupling constant"`）
  - `factors`: 正式名 → 正準単位への係数
  - `aliases`: 別名 → 正式名
- `UnitKind.resolve(written: object) -> ResolvedUnit` を足す。`ResolvedUnit` は
  `text`（正式形）と `factor`（倍率 × 正式名の係数）を持つ。検証前のファイルの値を
  受けるので `object` で取り、文字列でなければ誤りとする。未知の名前や書き方の誤りは
  `UnsupportedUnitError` で、報告には正式名と別名の一覧、受け付ける書き方を載せる。
- 倍率と名前の切り分け（上の規則）は単位の種類に依存しないので、`resolve` の外の関数に
  置く。`inputs.py` の coupling の欄が、流儀が分かる前に書き方だけを確かめるのに使う。
- `ENERGY_UNITS`（正式名 → 係数）はそのまま残し、別名の表 `ENERGY_UNIT_ALIASES` と
  まとめた `ENERGY_UNIT_KIND` を足す。`energy_conversion_factor(unit)` は
  `ENERGY_UNIT_KIND.resolve(unit).factor` を返す薄い関数として残す（テストが使っている）。
- `CouplingConvention.energy_power: float | None` を `unit_kind: UnitKind | None` に
  置き換える。`None` なら無次元である。`LAMBDA` は `ENERGY_UNIT_KIND` を持つ。
  `coupling_to_canonical(unit)` は `unit_kind.resolve(unit).factor` を返す。
  `check_coupling_unit` の「単位が要る」という報告は、べき指数の代わりに
  `unit_kind.name` を載せる。
- V の単位の種類と流儀 `vcc` は ADR-0077 が足す。

### `inputs.py`

- **エネルギーの欄**（`frequency_unit` / `_EnergySpec.unit` と、`frequency` / `sigma` /
  `e_min` / `e_max` / `points.de` に添えた単位）は、単位の種類が欄から決まる。検証器で
  `ENERGY_UNIT_KIND.resolve(...)` を呼び、**正式形を保存する**。今の
  `energy_conversion_factor(value); return str(value)` を置き換える形になる。
- **coupling の欄**（`coupling_unit` と `modes[].coupling` に添えた単位）は、単位の種類が
  流儀で決まり、フィールドの検証器からは流儀が見えない。そこで次の 2 段で扱う。
  1. `FCEnvelopeInput` に `model_validator(mode="before")` を足し、生の辞書の段階で
     coupling の欄の単位を正式形へ置き換える。流儀は生の `coupling_convention`（なければ
     既定）から引く。流儀の名前が未知なら何もせず返す（フィールドの検証器が報告する）。
     無次元の流儀でも何もせず返す（`to_system` の `check_coupling_unit` が今までどおり
     報告する）。置き換えるのは `coupling_unit` が文字列のときと、`modes` がリストで、
     その要素が辞書で、`coupling` が長さ 2 のリストで 2 つ目が文字列のときだけである。
     それ以外の形は触らずに残し、構造の誤りはフィールドの検証器に報告させる。
     `{"path": ...}` のモード表は CSV で、単位を持たないので対象外である。呼び出し側の
     辞書は書き換えず、写しを返す。誤りの報告には位置（`coupling_unit: ...` /
     `modes[2].coupling: ...`）を添える。
  2. `ModeSpec.coupling` の型は、書き方（倍率と名前の切り分け）だけを確かめて単位の
     文字列をそのまま保つものにする。エネルギーの欄の型と分け、今の `Dimensioned` を
     エネルギー用と coupling 用の 2 つにする。`coupling_unit` の検証器も書き方の検査
     だけにする。
- `Quantity.in_canonical` は `ENERGY_UNIT_KIND.resolve(...)` の `factor` を使う。保存
  されているのは正式形で、正式形は冪等に読めるので、変換の側は別名も倍率も意識しない。
- `to_json` は変更不要である。モデルが正式形を持っているので、そのまま正式形が出る。

### テスト

- 倍率と名前の切り分け: `"hartree"`、`"1e-4 hartree"`、`"10^-4 hartree"`、`"  2.5   eV "`
  を受け付け、`"1e-4a.u."`、`"0 eV"`、`"-1 eV"`、`"nan eV"`、`"1 2 eV"`、`""` を
  `UnsupportedUnitError` で拒否する。
- 係数: `"10^-3 eV"` の係数が `eV` の係数の 1e-3 倍、`"a.u."` が `hartree` と同じ。
- 正式形: `"10^-4 a.u."` がエネルギーの欄では `"10^-4 hartree"` になる。すべての正式名、
  別名、倍率つきの組み合わせで、正式形を読み直すと同じ正式形になる。
- 入力: `sigma = [x, "a.u."]` と `sigma = [x, "hartree"]` が同じ `Broadening` になる。
  `grid.unit = "10^-3 eV"` の窓が meV で読まれる。
- 実効設定: 別名で書いた入力の `to_json` に別名が残らず正式形が出る。その出力を読み直すと
  同じ系・同じ条件になる。
- 上書き: `--override broadening.sigma='[1.0, "a.u."]'` が通る。
- 流儀との噛み合わせ: 流儀 `lambda` の `coupling_unit = "a.u."` が `hartree` になる。
  無次元の流儀に `"a.u."` を添えると今までどおり拒否される。
- 既存のテストのうち、`CouplingConvention(..., energy_power=...)` を組み立てているもの
  （`test/test_conventions.py`）と、誤りの文言に合わせているものは新しい形に直す。
