# 2 つのエンベロープの違いを差のノルムで数にする

- 日付: 2026-10-22
- 状態: 受理

温度・線形状・`scale_huang_rhys`（ADR-0087）を振ったときにスペクトルがどれだけ変わるか、
グリッドを細かくしたときに収束しているか、を図を見比べるのではなく数で言いたい。そのために
2 つのエンベロープの差 F₁ − F₂ のノルムを返す自由関数を足す。

```python
from fcenvelope import envelope_distance

envelope_distance(result_300k, result_77k, norm=1)     # 1, 2, math.inf のどれか
```

| `norm` | 定義 | 単位 | 値の範囲 |
|---|---|---|---|
| `1` | ∫\|F₁ − F₂\| dE | 無次元 | 0〜2 |
| `2` | (∫\|F₁ − F₂\|² dE)^½ | (cm⁻¹)^−½ | 0 以上 |
| `math.inf` | max \|F₁ − F₂\| | 1/cm⁻¹ | 0 以上 |

## 決まりごと

- **比べるのは本プログラムが計算したエンベロープ同士だけ。** 引数は `EnvelopeResult` 2 つで、
  配列や外部のスペクトルは受けない。結果ファイルからは `load_envelope` で読んで渡す。
- **ノルムは E 軸上の積分として定義する。** 出力グリッドの和に ΔE を掛けた長方形則で近似
  する（`total_area` の診断値と同じ和）。`np.linalg.norm(F1 - F2)` のままだと値がグリッドの
  細かさで変わる。L1 は被積分関数が交点で折れるので、長方形則の誤差が ΔE の 1 次で残る。
- **`norm` に既定値を置かない。** ノルムごとに単位が違い、どれが「普通」とも言えないため。
  受けるのは `1`・`2`・`math.inf`（numpy の `ord` と同じ書き方）で、ほかは
  `InvalidInputError` にする。
- **2 つの出力グリッドは同じ点でなければならない。** ΔE か窓が違えば補間せずに
  `InvalidInputError` で止め、どちらが違うかを言う。`n_fft` だけが違う（ΔE と窓が同じ）
  なら出力の点は同じなので比べられ、全域グリッドの広さによる折り返しの影響を測るのに使える。
- **規格化はやり直さない。** どちらも全域グリッドで ∫F dE = 1 に揃っている。窓の中で規格化
  し直すと、窓の外へ逃げた面積の差が隠れる。返すのは出力窓の上での差のノルムである。
- **系・温度・線形状の違いは警告しない。** 違う条件を比べるのがこの関数の目的である。
  重ね描きが条件の食い違いを警告する（ADR-0029）のとは逆で、あちらは同じ条件であることが
  図の前提だからである。
- **ライブラリだけの口とする。** CLI にも入力ファイルにも足さない。

## 理由

**後処理として ADR-0001 の範囲に収まる。** 計算するものは変わらず、計算した 2 つの結果の
間の量を返すだけである。実験スペクトルや外部の配列を受け始めると、任意単位の規格化、E 軸の
原点合わせ、吸収・発光の周波数因子が要り、ADR-0001 / 0017 の外へ出る。引数を
`EnvelopeResult` に限ると、E 軸も規格化も本プログラムの定義どおりであることが型で保証され、
そうした選択を持ち込まずに済む。

**補間しない。** 補間の誤差は、測りたい差と同じ桁になりうる。とくに ΔE を変えた収束の確認
では、比べたいのがまさに ΔE による違いである。窓の外を 0 とみなす案も採らない。データが
無いところを 0 と言うことになる。どちらのグリッドも入力ファイルで明示的に決めたもの
（ADR-0006, 0070）なので、揃えるのは利用者にとって難しくない。違うグリッドの結果を
どうしても比べたいなら、`np.interp` で自分で補間すればよく、その誤差の判断も利用者がする。

**CLI に出さない。** 返すのはスカラー 1 つで、CLI にすると出力の形（端末に出す数の書式、
ファイルに残すか）を新たに決めることになる。結果ファイル 2 つからでも
`envelope_distance(load_envelope(a), load_envelope(b), norm=1)` の 1 行で済む。
`scale_huang_rhys` をライブラリだけにした ADR-0087 と同じ判断である。シェルから繰り返し
呼ぶ必要が出たら別の ADR で決める。

## 採らなかった案

- **線（`LinesResult`）にも同じ関数を足す。** 線の集合はエネルギーの位置も本数も結果ごとに
  違い、「差」を定義するには線をどう突き合わせるかを決めなければならない（ゴールデンケース
  ではエネルギーの許容差でまとめている。ADR-0082）。突き合わせの規則は用途ごとに違いうるので、
  ここでは決めない。線同士を比べたいなら、同じ線形状と同じグリッドで計算したエンベロープを
  比べれば足りる。
- **ゴールデンケースの比較をこの関数に寄せる。** `test/test_golden.py` の
  `envelope_deviation` は、縦軸が任意単位の外部の参照データ（CSV）を相手にするので、参照の点
  へ補間し、両方を面積 1 に正規化し、参照の最大値で割る。どれもこの関数がしないと決めた
  ことである。相手も `EnvelopeResult` ではない。比較はテストに置くという ADR-0082 の判断は
  そのまま残す。
- **相対ノルム ‖F₁ − F₂‖ / ‖F₁‖ も返す。** どちらを分母にするかの選択が入るうえ、1 行の
  割り算で書ける。
- **ノルムを任意の p にする。** 使い道が思い当たらず、受ける値を増やすと検証が要る。必要に
  なれば `NORMS` に足せばよい。

## 帰結

- 語彙として「エンベロープの距離」を CONTEXT.md に足す。
- 新しいモジュール `distance.py`（依存先は errors, result）を置く。`envelope.py` は計算、
  こちらは計算済みの結果の間の量で、責務が違う。
- 出力ファイル・入力ファイル・CLI は変わらない。
