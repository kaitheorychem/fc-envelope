# 結果ファイルの単位は入力ファイルと同じ書き方で、値と表の列に添える

- 日付: 2026-09-24
- 状態: 受理（ADR-0047 の「単位はヘッダの `energy_unit` / `density_unit` に書く」を置き換える。
  単位を結果クラスではなく `io` が持つ、は変わらない。同日、表の単位を `<列名>_unit` から
  `columns` に改めた。版 4 の結果ファイルを出す前の改訂なので、版は上げない）

結果ファイルはヘッダに `energy_unit = "cm^-1"` / `density_unit = "1/cm^-1"` を書き、値は素の数で
持っていた。これには 2 つの問題があった。

- ヘッダの欄は、ほかの単位も書けそうに見える。しかし読み込み側は `cm^-1` 以外を落とし、作図
  スクリプトはこの欄を読んでいなかった。
- 単位が書いてあるのは一部の量だけだった。σ・グリッド・λ・`d_tau` / `tau_max`・`mean_energy`
  の単位は、ファイルのどこにも書かれていなかった。

**結果ファイルの単位は、入力ファイルと同じ 2 つの書き方で書く。**

- 有次元の値 1 つは `[値, "単位"]` の組にする（入力の値に単位を添える形、ADR-0072）。
- 表は `columns` と `rows` で書く。`columns` は列名か `[列名, "単位"]` の並び、`rows` は 1 行ごとの
  値の並びである（入力の CSV の `columns`、ADR-0079 と同じ書き方）。

```json
"conditions": {
  "modes": { "columns": [["frequency", "cm^-1"], "huang_rhys"], "rows": [[1200.0, 0.25]] },
  "temperature": 300.0,
  "broadening": { "sigma": [150.0, "cm^-1"] },
  "grid": { "e_min": [-4500.0, "cm^-1"], "e_max": [1000.0, "cm^-1"], "de": [4.0, "cm^-1"], "n_fft": 4096 }
},
"derived": { "reorganization_energy": [300.0, "cm^-1"] },
"diagnostics": { "d_tau": [3.83e-4, "cm"], "tau_max": [0.785, "cm"], "sigma_tau_max": 117.8, "...": "..." },
"spectrum": {
  "columns": [["energy", "cm^-1"], ["density", "1/cm^-1"]],
  "rows": [[-4500.0, 4.6e-8], [-4496.0, 4.4e-8], "..."]
},
"lines": {
  "columns": [["energy", "cm^-1"], "fc_factor", "weight", "transitions"],
  "rows": [[-450.0, 0.26, 0.23, [{ "mode": 2, "initial": 0, "final": 1 }]], "..."]
}
```

## 決まりごと

- 組にするのは有次元の値だけである。無次元の値（S、FC 因子、重み、割合、比、点数、真偽）と
  温度は素の数で書く。温度を素の数（K）で書くのは入力ファイルと同じである。
- 表の有次元の列は必ず `[列名, "単位"]` で書き、無次元の列は列名だけで書く。入力の CSV では
  単位を省いた列を `[modes]` の既定の単位で読むが、結果ファイルには既定の単位がないので、
  有次元の列の単位は省けない。
- 単位の文字列は正式名で書く。書き出す単位は常に正準単位（エネルギー `cm^-1`、密度
  `1/cm^-1`、τ `cm`）である。
- 読み込みは列を名前で引く。`columns` の並びは問わないが、決まった列をちょうど 1 回ずつ
  並べ、各行の値の数は列の数に揃っていなければならない。正準単位以外の単位は
  `UnsupportedUnitError` で止める。入力ファイルが知らない単位を拒むのと同じ、値の検証である。
- 線の `transitions` 列の値は、遷移（`{"mode", "initial", "final"}`）の並びである。1 本の線に
  関わるモードの数は線ごとに違うので、列に展開せず 1 つの値として持つ。
- ヘッダの `energy_unit` / `density_unit` はなくす。
- 書き出しは入れ子を字下げし、`[値, "単位"]` や `columns` のような平たい並びは 1 行に、表の
  `rows` は 1 行ずつ書く。人が覗いたときに CSV と同じ見え方になり、ファイルも小さくなる。
  値の書き方は `json` のままなので、round-trip で値は変わらない（ADR-0008）。

## 理由

プログラム全体で単位の書き方を 1 通りにそろえる。入力ファイルにはすでに「値に添える組」と
「CSV の列に添える `[列名, "単位"]`」があり、結果ファイルはこの 2 つを使うだけで、新しい
書き方を足さない。マニュアルで入力の書き方を覚えた人は、結果ファイルもそのまま読める。

表の単位を `energy_unit` のような `<列名>_unit` の欄で書く案も一度採った。入力の `[modes]` の
`frequency_unit` と同じ形だが、あれは行を直接書くときの**既定**の単位で、結果ファイルの列の
単位とは役割が違う。列の単位そのものを書く場所は、入力では CSV の `columns` なので、そちらに
合わせた。

ヘッダに単位を固定で宣言する案（単位の表を 1 つ置き、値は素の数）も検討した。値が素の数の
まま読めるのが利点である。採らなかったのは、入力と違う書き方が増えるためである。1 つの値を
見ただけで単位が分かることも優先した。

長い表（スペクトル・線）を入力と同じように CSV へ切り出す案も検討した。採らなかったのは、
結果ファイル 1 つから結果を完全に復元できる性質（ADR-0010）を失い、出力が複数のファイルに
分かれて、作図スクリプトや重ね描きが相方のファイルの置き場所を管理することになるためで
ある。表の形は CSV と同じ（列の宣言と行の並び）なので、必要になれば機械的に書き出せる。

## 帰結

- 結果ファイルの版は 4 のまま（ADR-0080 と同じ変更の範囲で、版 4 の結果ファイルはまだ
  使われていない）。
- 作図スクリプトの雛形は、表から列を名前で取り出す `column(table, name)` を持つ。σ は
  `sigma[0]` で読む。
- `io` の表の列は `_MODE_COLUMNS` / `_SPECTRUM_COLUMNS` / `_LINE_COLUMNS`、単位を持つ診断値は
  `_DIAGNOSTIC_UNITS` に並べる。列や診断値を足すときは、有次元ならここに単位も書く。
