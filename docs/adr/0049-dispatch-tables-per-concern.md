# 結果の種類による振り分けを、関心ごとの表にする

- 日付: 2026-09-17
- 状態: 受理

結果の種類（`kind`）による分岐が 4 箇所に散っていた。`io.load_any` の if 文、CLI の
`_save_figure` と `_pair_for_overlay` の `isinstance`、CLI の報告関数である。今の予定に
種類を増やす機能はないが、将来増える可能性は十分ある。また、分岐が複数箇所に残っていると、
種類を増やさない場合でも読むたびに漏れがないか確かめることになる。新しい分岐を書くときにも
既存の if 文が真似されやすい。そこで表で振り分ける。

表は関心ごとに、その関心を持つモジュールに置く。

| モジュール | 表 |
|---|---|
| `io.py` | `kind` → 保存・読み込み |
| `plotting.py` | 結果の型 → 描画 |
| `cli.py` | 結果の型 → 報告 |

種類を足すときは各表に 1 行ずつ足す。すべての表が同じ種類を網羅していることをテストで
確かめる。

## 検討した選択肢

- **1 つの表にまとめる**（種類ごとに保存・読み込み・描画・報告をまとめた記述オブジェクトを
  登録する）案は採らない。種類ごとの情報が 1 箇所に集まる一方、表を置いたモジュールが io・
  描画・CLI のすべてに依存する。ライブラリとして読み込むだけで描画の関数を参照することに
  なり、ADR-0041 の依存の向きが崩れる。
- **結果クラスのメソッドにする**案は ADR-0011 に反するので採らない。

## 帰結

重ね描きは表に載せず、専用の関数のままにする。重ね描きは種類ごとの処理ではなく、
「エンベロープと線」という特定の組み合わせに対する処理だからである。CLI の組み合わせの
判定でも、エラー文の種類名は表から引き、`kind` 文字列を直接書かない。
