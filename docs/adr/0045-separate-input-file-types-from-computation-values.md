# 入力ファイルの型と、計算に渡す値の型を分ける

- 日付: 2026-09-17
- 状態: 受理（ADR-0007 の「境界は pydantic、内部は dataclass」を入力にも適用する）

これまで `Conditions` は「ファイルでの形と計算用の値が一致する」という理由で、pydantic
モデルを両方に使っていた。`FCEnvelopeInput` はファイルの構造、CSV の解決、単位の検査、
正準化をまとめて担っていた。

これを 2 つに分ける。

- **入力ファイルの型**（`inputs.py`、pydantic）: ファイルの構造、単位、流儀を扱い、正準化して
  計算用の値を返す。
- **計算用の値の型**（`models.py`、frozen dataclass）: `VibrationalMode`,
  `VibrationalSystem`, `Broadening`, `EnergyGrid`, `Selection`。常に正準形で、pydantic に
  依存しない。

理由は、直近で予定している単位変換を入れると「ファイルの形と計算用の値が同じ」という
前提が σ や `e_min` でも崩れるからである（例: eV で書かれた σ）。分けておけば、入力の
見直しはファイル側だけ、計算の変更は値の側だけで済む。

## 帰結

結果ファイルの入力エコーは常に正準形（ADR-0010）なので、`io` は結果を読み込むときに
入力ファイルの型を経由せず、値の型を直接作る。
