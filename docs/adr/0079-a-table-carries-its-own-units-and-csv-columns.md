# モード表は単位と流儀を自分で持ち、CSV は列の並びと単位で表に差し替える

- 日付: 2026-09-24
- 状態: 受理（ADR-0019 の参照の形、ADR-0020 の列の決まりの一部、ADR-0053 の
  `frequency_unit` / coupling の単位の置き場を置き換える。単位の軸を項目ごとに独立させる
  という ADR-0053 の考え方そのものは変えない）

入力ファイルのトップレベルには `frequency_unit` / `coupling_convention` / `coupling_unit`
があった。これらが効くのはモード表の列だけである（ADR-0053）。それなのにトップレベルに
置かれているせいで、ファイル全体に効く共通の単位に見える。CSV でモードを渡すときは、
CSV に書けない単位をこのトップレベルの欄が補っていた（ADR-0019）。

**表として受け取る欄は、その表の既定（単位と流儀）を表のブロックに持つ。表の行は直接
書くか、CSV の列の並びと単位を書いて CSV から読むかのどちらかにする。** 今のところ表として
読む欄はモード表だけで、トップレベルに単位の欄は残らない。

```toml
schema_version = 4
temperature = 300.0

[modes]
coupling_convention = "vcc"      # coupling の列の意味
frequency_unit = "cm^-1"         # frequency の列の既定の単位。省略時は cm^-1
coupling_unit = "a.u."           # coupling の列の既定の単位。有次元の流儀のときだけ

[[modes.rows]]
frequency = 1200.0
coupling = [1.5, 1e-4, "a.u."]   # 値に添えた単位が既定に勝つ（ADR-0072）
```

```toml
[modes]
coupling_convention = "vcc"
coupling_unit = "a.u."
csv = { path = "modes.csv", columns = [["frequency", "eV"], "coupling"] }
```

## 決まりごと

- `[modes]` には `rows` と `csv` のどちらか一方だけを書く。
- `csv` のキーは `path` と `columns`。`path` の相対パスは入力ファイルのディレクトリを
  基準にする（ADR-0019 のまま）。
- `columns` は列の並びで、各要素は列名か、列名に単位を添えた組である。組の形は値に単位を
  添える形（ADR-0072, 0078）と同じで、値の位置に列名が入る。
  `"coupling"` / `["coupling", "a.u."]` / `["coupling", 1e-4, "a.u."]`。
- `columns` を省略すると `["frequency", "coupling"]` と同じである。単位を添えない列は
  `[modes]` の既定の単位で読む。したがって何も書かなければ ADR-0019 と同じ読み方になる。
- `columns` は表の列をちょうど 1 回ずつ並べる。補助列は受け付けない（ADR-0020 のまま）。
- CSV のヘッダは省略できる（ADR-0020 のまま）。ヘッダがあり `columns` を書かなかった
  ときは、ヘッダの並びで読む。ヘッダがあり `columns` も書いたときは、両者の並びが
  一致しなければ誤りとする。どちらを信じるべきかをプログラムが決められないためである。

## 理由

単位の決まり方を、行を直接書く場合と CSV を読む場合とで揃える。

| 行を直接書く | CSV を読む |
|---|---|
| 値に添えた単位 `[0.05, "eV"]` | 列に添えた単位 `["frequency", "eV"]` |
| `[modes]` の既定の単位 | `[modes]` の既定の単位（同じもの） |

CSV には数しか書けないので、CSV の値に単位を添える場所は列しかない。列に添えた単位を
その列のすべての値に添えたものとして読めば、CSV を読んだ後は行を直接書いた場合と区別が
なくなる。単位を解決する仕組みは 1 つで足りる。

列の単位を `units = { frequency = "eV" }` のように列の並びと別に書く案も検討した。列の
並びだけ、または単位だけを変えたいときに片方を書かずに済むのが利点である。採らなかった
理由は、列名に単位を添える形が値に単位を添える形とそのまま重なり、覚える書き方が増えない
ためである。既定の単位で読むなら、列の並びは `["frequency", "coupling"]` と名前だけで書ける。

`coupling_convention` も `[modes]` に移す。流儀は coupling の列の意味そのものであり、
モード表の外では何にも効かない。

## 帰結

- `schema_version` を 4 へ上げる。互換層は置かない（ADR-0040 と同じ）。版 3 の入力は
  `SchemaVersionError` になる。`[[modes]]` の並びとトップレベルの単位の欄は、版 4 では
  書けない。
- 結果ファイルの形と版（3）は変えない。入力エコーは正準形（cm⁻¹・huang_rhys）で書かれ、
  既定の単位という考え方を持たないためである（ADR-0010）。入力ファイルと結果ファイルの
  版の番号を共有するという取り決め（`io.SCHEMA_VERSION` の注記）はここで終わる。
  結果ファイルの版を上げると、生成済みの作図スクリプトが新しい結果ファイルを読めなくなる
  （ADR-0060 によりスクリプトは上書きされない）。版を据え置けばその影響は出ない。
- 実効設定（ADR-0065）では、CSV は行に展開される。列に添えた単位は各値に添えた形で
  書き出されるので、そのまま入力として読み返せる。
- `--override` は `modes` の下を上書きできない（ADR-0012 のまま）。流儀も `modes` の下に
  入るので上書きできなくなる。値を変えずに流儀だけを差し替えても、同じ分子を別の意味で
  読むだけなので失うものはない。
- CSV を読む部分は、列の並びと単位を受け取って値に単位を添えた行を返す汎用の関数と、
  その行をモードとして検証する部分に分ける。表として読む欄が増えたときは前者を使い回す。
