# 横軸がぴったり同じ線は描くときに重みを足す

- 日付: 2026-11-06
- 状態: 受理（ADR-0025 の「結果の線をまとめない」はそのまま。描画の側だけを変える）

熱占有のある温度では、量子数の差 Δn = m − n の組が同じ遷移（n → n+k の系列）が同じ
エネルギーに何本も立つ。`basic.toml`（300 K）では 58 本が 25 か所に、`test_emit.py` の
3 モード系では 132 本が 52 か所に重なる。1 本ずつ描くと最大のものしか見えず、その位置に
立つ重みの合計が図から読めない。

そこで棒スペクトルを描くとき（作図スクリプトの `lines` と重ね描き、ライブラリの
`plot_lines` / `plot_overlay`）は、エネルギーがぴったり同じ線の重みを足して 1 本に描く。
結果ファイルと `LinesResult` の線、端末に出す上位 N 本の表は 1 本ずつのまま残す。

作図スクリプトには `MERGE = True` を、ライブラリには `merge=True` を置き、False にすれば
1 本ずつ重ねて描く以前の描き方に戻る。

## 理由

**まとめるのは表示の都合で、計算結果の性質ではない。** ADR-0025 が線をまとめないのは、
量子数のラベルが「どのモードが効いているか」を読む手がかりだからで、その理由は今も変わら
ない。足し合わせが要るのは縦軸の高さを読むときだけなので、描く直前に行う。

**許容誤差を置かず、完全一致で比べる。** `compute_fc_lines` はモードを決まった順に
`E − (m − n)ω` と積み上げるので、Δn の組が同じ線はビット単位で同じエネルギーを持つ。
重なりの大半はこれで、`basic.toml` では小数 6 桁に丸めて数えても組は変わらなかった。
Δn の組が違うのに名目上同じエネルギーになる偶然の縮退は、最後の桁が違って足されない
ことがある。許容誤差を入れると近い線が数珠つなぎにまとまり、どこまでを同じとみなすかと
いう新しい設定も増えるので、置かない。

**比べるのは cm⁻¹ の生の値で、横軸を移す前に行う。** `X_SCALE` で eV に換算したり
`REF_GAP` で ε 軸に移したりした後の値は、丸めで一致が崩れることがある。

**重ね描きでは足した高さがそのまま F(E) の山に対応する。** F(E) は線を線形状で畳んで
足し上げたものなので、同じ位置の線は山の高さに和として効く。孤立した位置では、足した
棒の先端が曲線の山に一致する（ADR-0027）。

## 帰結

- 縦軸の `weight` は「その位置に立つ重みの和」になる。総和が 1 であることは変わらない。
- `plot_modes` は棒を描く部分を共有しているが、足し合わせない。g は足して意味を持つ量では
  ないからである。
- 既に書き出された作図スクリプトは書き換わらない。足して描くには `--force-script` か
  `script --force` で作り直すか、`stack` と `MERGE` を手で写す。
