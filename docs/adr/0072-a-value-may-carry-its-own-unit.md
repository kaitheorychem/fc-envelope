# 有次元の値は `[値, "単位"]` の組でも書ける

- 日付: 2026-09-20
- 状態: 受理（ADR-0053 の「単位の軸は項目ごとに独立」を、書き方の側へ広げる。軸の分け方
  そのものは変えない）

単位は今、値とは別の項目に書く。σ の単位を eV にしたければ次のように書く。

```toml
[broadening]
sigma = 0.0186
unit = "eV"
```

`unit` の行は σ ひとつのためだけにある。値と単位が別の行に離れており、ブロックを見ないと
どちらの単位で書いたのか分からない。**有次元の値そのものに単位を添えて書けるようにする。**

```toml
[broadening]
sigma = [0.0186, "eV"]
```

受け付ける書き方はちょうど 3 つで、どれも同じ量を表す。

| 書き方 | 意味 |
|---|---|
| `sigma = 150.0` | 既定の単位（ブロックの `unit`、省略時は `cm^-1`） |
| `sigma = [150.0]` | 同上。組の形のまま単位を省いたもの |
| `sigma = [0.0186, "eV"]` | 添えた単位で読む |

組を書ける場所は**有次元の値**、すなわち `modes[].frequency` / `modes[].coupling` /
`broadening.sigma` / `grid.e_min` / `grid.e_max` / `grid.points.de` の 6 つである。
無次元の値（`grid.points.n` / `shift` / `selection` の各つまみ）には書けない。温度は
K 固定で単位の軸を持たないので、ここにも入らない。

## 理由

**ブロックの `unit` は残す。値に添えた単位があればそれが勝ち、なければブロックの単位で
読む。** 単位の指定を組へ一本化はしない。理由は 2 つある。

`grid` は `e_min` / `e_max` / `points.de` の 3 つが同じ軸を共有する。ここで `unit` を
取り上げると、同じ単位を 3 回書かせることになる。1 か所で決められる口は残すほうがよい。

`modes` は CSV でも渡せる（ADR-0019）。CSV に単位の列は置けないので、モードの単位を
担うのは入力ファイルの側でなければならない。`frequency_unit` / `coupling_unit` は
この理由で存在しており、組では置き換えられない。

したがって組は、既存の単位指定を**置き換えるもの**ではなく、値の側に寄せて書ける
**もう一段細かい指定**である。ブロックの単位は既定値として働く。

## 検討した選択肢

**単位付きの文字列（`sigma = "0.0186 eV"`）**: 設定ファイルで見かける書き方としては
こちらのほうが多く、物理屋の手書きにも近い。採らない理由は、数値が文字列の中に隠れる
ことである。組なら TOML / JSON の数値がそのまま数値として渡り、`--override` の値が
JSON として読まれる経路（ADR-0064）にも手を入れずに済む。文字列にすると
`0.0186eV` / `0.0186 eV` / `1.86e-2 eV` のような書き方の揺れを自前で吸収することになり、
単位名の側にも `cm^-1` や `kJ/mol` のような記号が入っているので、区切りの規則を決める
のも面倒である。

**インラインテーブル（`sigma = {value = 0.0186, unit = "eV"}`）**: 独自ルールでない点は
組と同じだが、長い。同じことを 2 通りに書けるようにする理由がないので受け付けない。

**組へ一本化してブロックの `unit` を廃止する**: 上の理由で採らない。加えて、廃止すれば
既存の入力ファイルが全部読めなくなり `schema_version` を上げることになる。

## 帰結

`[値, "単位"]` は**追加**なので、単位を書いていない入力ファイルも、ブロックの `unit` で
書いた入力ファイルも、これまでと同じ意味で読める。`schema_version` は 3 に据え置く
（ADR-0053 と同じ上位互換の追加）。

`inputs.py` に有次元量の型 `Quantity(value, unit)` が増える。3 つの書き方を 1 つの形へ
畳むのはこの型で、`unit` が `None` なら既定の単位で読む。正準化は
`Quantity.in_canonical(既定の単位)` に集まり、変換が入力の境界だけで起こることは
変わらない（ADR-0054）。

モードごとに単位を書けるようになるので、coupling の換算係数はモードごとに引く。無次元の
流儀に単位を添えた誤りは、これまでのファイル全体に対する 1 回の検査から、そのモードを
名指しする報告（`modes[2]: ...`）になる。

実効設定（`*_config.json`）は**書いたままの姿**で書き出す。素の数値で書けば素の数値、
組で書けば組である。ブロックの `unit` は省略しても既定値で埋まって必ず書かれるので、
どちらで書いても実効設定だけを見れば単位は分かる（ADR-0065）。

`--override` は値を JSON として読むので、そのまま組を渡せる。

```bash
--override broadening.sigma='[0.0186, "eV"]'
```

これまで値と単位で 2 回に分けていた上書きが 1 回で済む。
