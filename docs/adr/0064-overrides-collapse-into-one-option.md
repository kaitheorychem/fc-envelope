# 個別の上書きオプションを畳み、`--override key=value` に集約する

- 日付: 2026-09-20
- 状態: 受理（ADR-0012 の上書き対象と ADR-0050 の単位の規則はそのまま。口だけを変える）

`--temperature` / `--sigma` / `--e-min` / `--e-max` / `--de` / `--min-weight` /
`--max-lines` / `--max-quanta` を廃し、繰り返し指定できる `--override KEY=VALUE` 1 つに
まとめる。

```
fcenvelope run input.json --override temperature=0 --override grid.de=2.5
fcenvelope lines input.json --override selection.max_quanta=null
```

| 決め | 内容 |
|---|---|
| キー | **入力ファイル中の項目の位置**。入れ子はドットで繋ぐ（`grid.de`, `broadening.sigma`） |
| 値 | JSON として読む。読めなければ文字列（`null` / `2.5` / `eV` が同じ規則で通る） |
| 単位・流儀 | 入力ファイルのもの（ADR-0050）。キーがファイルの位置なので、どの単位で読まれるかがキーから分かる |
| 拒否する位置 | `modes` 以下（ADR-0012）と `schema_version` |
| 誤字 | 入力ファイルの型が `extra="forbid"` なので、そのまま未知フィールドとして弾かれる |

これまでは入力ファイルに項目が増えるたびに CLI のオプションも増え、`run` と `lines` で
顔ぶれの違う一覧がヘルプに並んでいた。つまみの出どころは入力ファイルの構造 1 つなので、
CLI 側にその写しを持たない。単位の規則（ADR-0050）も、キーがファイルの位置そのものに
なったことで説明が要らなくなる。

## 帰結

失うのは typer による型検査・補完と、項目ごとのヘルプ文である。型と範囲の検査は入力
ファイルの型と値の型に残っており（ADR-0051）、誤りの報告もそこからの 1 本道になる。
ただし誤りの報告が使用法エラー（終了コード 2）から入力の誤り（終了コード 1）に移る位置
がある。`=` がない・キーが空・`modes` を指す、といった**書式そのものの誤り**だけが
使用法エラーのままである。

項目ごとのヘルプ文が消えるぶん、上書き後に実際に使われる設定は別の口で見せる（ADR-0065）。

短縮形 `-O` は置かない。`-o`（出力）と 1 文字違いで、取り違えると意味がまるで違う。

残るフラグとの線引きは「**入力ファイルに書けるものは `--override`、その実行だけの話は
フラグ**」とする。`--top` / `--log` / `--script` / `--no-script` / `--force-script` /
`--config` / `--no-config` は後者で、入力ファイルには書けない。
