# ブロックが必須かどうかは、それを読む副命令が決める

- 日付: 2026-09-22
- 状態: 受理（ADR-0005 / ADR-0035 の「1 ファイルを両方の副命令が使う」を、必須性の面から詰める）

`run` と `lines` は同じ入力ファイルを読み、読む場所だけが違う（ADR-0005, 0035）。

| 位置 | 読む副命令 |
|---|---|
| `modes` / `temperature` / `frequency_unit` / `coupling_convention` / `coupling_unit` | 両方 |
| `broadening` / `grid` | `run` だけ |
| `selection` | `lines` だけ |

ところが `broadening` と `grid` は入力ファイルの型の**必須フィールド**だったため、`lines`
しか使わない入力にも、使われないグリッドを書かないとパースが通らなかった。

```
$ fcenvelope lines linesonly.toml
error: 2 validation errors for FCEnvelopeInput
broadening
  Field required
grid
  Field required
```

`selection` には既定値があって `run` からは省略できるので、この制約は片側にしか効いて
いない。両方を省略可能にし、**無いことを報告するのは読む側の `to_broadening()` /
`to_grid()` にする**。

```
$ fcenvelope lines linesonly.toml     # 通る
$ fcenvelope run   linesonly.toml
error: broadening: required by `fcenvelope run` (add a [broadening] block with sigma)
```

## 既定値で埋めない理由

「省略できる」を「既定値が入る」で実装しない。σ は現象論的なモデルパラメータ、E 窓は
どこを見るかの選択で、どちらも分子と目的ごとに決まる（ADR-0035）。ここに既定値を置くと、
書き忘れが黙って通って「それらしい」図になる。`temperature` に既定値を置かなかったのと
同じ判断である（ADR-0021）。

`selection` を既定値で埋め続けるのはこれと矛盾しない。`min_weight` / `max_lines` は
**どこで打ち切るか**のつまみで、分子によらない妥当な既定がある。

## 構造の検査と、必要かどうかの判定を分ける

入力ファイルの型が見るのはファイルの構造・単位・流儀だけである（ADR-0045）。「この計算に
この量が要る」は構造ではなく計算の側の事情なので、pydantic の必須フィールドではなく
`to_*` に置く。値の範囲を計算用の値の型が持つ（ADR-0051）のと同じ向きの分割である。

報告には**どの副命令がそれを必要とするか**を添える。省略できるのは読まない副命令から
見たときだけなので、「必須ではない」とだけ言うと直し方が分からない。

`run` が両方を書き忘れた場合、報告されるのは先に読む `broadening` だけである。pydantic は
2 つまとめて報告していたが、`to_system()` が最初の不正なモードで止まるのと同じ振る舞いに
揃える。この層は一度に 1 つ報告する。

## 検討した選択肢

**`[run]` / `[lines]` という副命令名のセクションを切る**案は採らない。ファイルの構造が
CLI の副命令名に縛られ、ライブラリ API の名前（`compute_envelope` / `compute_fc_lines`）と
ずれる。`diagonalize` を足せば（ADR-0037）セクションが増える。今の
`[broadening]` / `[grid]` / `[selection]` は**量の意味**で名前が付いていて、どの副命令が
読むかはそこから従属的に決まる。この向きのほうが壊れにくい。

**副命令ごとに入力ファイルを分ける**案も採らない。`modes` と `temperature` が両方に要るので
必ず重複し、片方だけ直したときに食い違う。1 ファイルで計算が再現できるという ADR-0005 の
狙いも失われる。

## 帰結

- `schema_version` は 3 のままである。必須を任意にするのは後方互換の変更で、今ある入力
  ファイルはすべてそのまま読める。版で区別する理由がない。
- 実効設定（ADR-0065）には書かなかったブロックが `"broadening": null` として現れる。
  JSON を選んだ理由がまさに「無しを書ける」ことなので（ADR-0069）筋は通っている。
  この JSON を入力として読み返しても、同じ副命令なら同じ計算になる。
- `--override` は `null` のブロックを「無い」と同じに扱う。`--override grid.e_min=-4000`
  でブロックごと起こせる（ADR-0064 の「知らない名前のブロックはそのまま作る」の延長）。
- 雛形（ADR-0074）は全ブロックを書いたままにする。どの副命令が読むかをコメントで言う。
  書き始める人が見たいのは「何が書けるか」であって、最小の入力ではない。
