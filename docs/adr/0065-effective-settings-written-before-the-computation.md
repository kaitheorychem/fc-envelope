# 実効設定を計算の前に JSON で書き出す

- 日付: 2026-09-20
- 状態: 受理

`run` と `lines` は、入力ファイルを読み終えて上書き（ADR-0064）を当てた直後、**計算を
始める前**に、その実行で実際に使われる設定を JSON で書き出す。既定の書き出し先は結果の
隣で、`result.json` に対して `result_config.json` である。`--config FILE` で場所を変え、
`--no-config` で書かせない。

書き出すのは正準化**前**の入力ファイルの型そのもの、すなわち**入力ファイルと同じ単位・
流儀**の値である。これを入力として与えれば同じ計算が再現できる。

| 見たいもの | 書き出しに現れる形 |
|---|---|
| 上書き後の値 | その項目の値が置き換わっている |
| 書かなかったので既定値になった項目 | 既定値が埋まって現れる（`selection` ブロックなど） |
| CSV で渡したモード | 行に展開されて埋め込まれる |

## 計算の前に書く理由

設定の確認は計算の成否と無関係で、重い計算が落ちても設定だけは手元に残ってほしい。
読み込みが終わった時点が「その実行の設定が確定した時点」でもある。

## 正準形ではなく入力ファイルの表現で書く理由

結果 JSON の入力エコーは常に正準形（`huang_rhys` / cm⁻¹）である（ADR-0010）。あれは
結果を読む側が流儀と単位を気にせずに済むためのもので、書き出しの狙いとは別である。σ を
eV で書いたファイルの利用者が確かめたいのは eV での値で、手元の入力ファイルと diff が
取れることに意味がある。役割が違うので両方を持ち、一方を他方から作らない。

## 上書きの方針

書き出し先は**常に上書きする**。作図スクリプト（ADR-0060）と逆になるのは、古いものを
残すと「この実行の設定」という名目が嘘になるからである。手で直して使うものでもない。

## 誤字について

誤字は書き出しを待たずに止まる。入力ファイルの型は `extra="forbid"` なので、知らない
フィールドは黙って無視されずエラーになる（ADR-0051 の範囲検査とは別の、構造の検査）。
書き出しが受け持つのは既定値・上書き後の値・再現の 3 つである。

## 再現の範囲

再現できるのは**入力**である。`fcenvelope_version` と `created_at` は実行のたびに変わり
（ADR-0008）、`derived` は系から決まる控えなので書き出しには入らない。同じ版に同じ設定を
与えれば同じ結果になる、という意味に限る。
