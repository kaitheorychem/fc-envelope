# 結果クラスの共通部分を、たまたま共通かではなく意味でまとめる

- 日付: 2026-09-17
- 状態: 受理

エンベロープと線の結果クラスには共通のフィールドが多い。ただし「今 2 つの結果で共通して
いるもの」を 1 つのオブジェクトにまとめることはしない。今後別の計算が加わったとき、共通に
使うのはそのうちの一部だけかもしれないからである。意味ごとに分ける。

| まとまり | 中身 | 扱い |
|---|---|---|
| 来歴 | `fcenvelope_version`, `created_at` | `Provenance` にまとめる。実行場所などを記録するならここに足す |
| 系 | モードの集まり | `VibrationalSystem`（ADR-0044） |
| 物理条件 | 温度 | 系とは別のフィールドとして持つ |
| 計算の補助 | 両系統で共有する閾値など | **今は該当なし。作らない** |

閾値を突き合わせたところ、エンベロープ側の 5 つと線側の 3 つに重なる値はなかった。
`EnergyGrid` と `Selection` もそれぞれ片方の系統専用である。

## 検討した選択肢

- **温度を系とまとめる**（`ThermalSystem(system, temperature)`）案は採らない。系は量子化学
  計算から来る分子に固有の情報で、温度は測定の条件である。同じ系を温度だけ変えて計算する
  のが典型的な使い方なので、まとめると「同じ分子で温度違い」を型の上で表せなくなる。重ね
  描きのチェックも、系の一致と温度の一致を別々に報告している（ADR-0029）。
- **共通部分を基底クラスにして継承する**案は採らない。ここで共有したいのはデータのまとまり
  であり、「エンベロープは結果の一種」という関係を主張したいわけではない。
