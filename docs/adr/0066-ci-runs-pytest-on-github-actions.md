# テストを GitHub Actions で走らせる

- 日付: 2026-09-20
- 状態: 受理

push（main）と pull request のたびに、GitHub Actions で `uv run pytest` を走らせる。
ワークフローは `.github/workflows/test.yaml` の 1 本だけである。

これまでテストは手元で走らせるだけだった。手元で緑であることと、リポジトリの main が
緑であることは別で、後者を確かめる場所が無かった。

## 手元と同じコマンドを走らせる理由

ワークフローが走らせるのは `uv sync --locked` と `uv run pytest` の 2 つで、README が
開発者に案内しているものと同じである。CI 専用の手順を作らないので、CI が落ちたときに
手元で再現する手段が「同じコマンドを打つ」に尽きる。

`--locked` を付けるのは、`uv.lock` を版管理に入れている以上、CI が勝手に解決し直して
手元と違う依存で緑になるのを避けるためである。lock と `pyproject.toml` がずれていれば
CI はそこで止まる。

## 3.11 と 3.13 の 2 つで走らせる理由

`requires-python = ">=3.11"` と書いてある以上、3.11 で動くことは約束である。開発は
3.11 で行っているが、利用者が新しい Python を使う場合もあるので、範囲の両端だけを見る。
間の版は、両端が通って間だけが落ちる事態が考えにくいので見ない。

`fail-fast: false` にしてあるのは、片方だけで落ちたときに「どちらの版の問題か」が
1 回の実行で分かるようにするためである。

## この 1 本に留める理由

型検査や lint は今のところ導入していない。入れていないものを CI に足しても落ちるだけ
なので、テストだけを見る。後で足すときは、この ADR ではなくそれぞれの導入を決める
ADR に属する。
