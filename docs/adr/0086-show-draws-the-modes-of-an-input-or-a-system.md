# show は入力ファイルやモードの系からも結合の図を出す

- 日付: 2026-09-30
- 状態: 受理（ADR-0084 の「保存済みの結果を」を広げる。ADR-0083 の作図スクリプトが結果
  ファイルを読むことはそのまま）

`show` は結果（計算した結果そのもの、または結果ファイルのパス）しか受けなかった
（ADR-0084）。そのため、結合の図を一目見るには、モードの表が手元にあっても一度 `lines` か
`run` で結果を作る必要があった。ライブラリでは `VibrationalSystem` を作っても `show` に
渡せず、捨てる線リストを作ってから `show(lines, modes=True)` とするか、窓にしか出ない
`plot_modes(system)` と `plt.show()` の組み合わせに降りるしかなかった。結合の図に要るのは
モードの系だけで、それは入力ファイル（とそこから辿る CSV）にすでに書かれている。

**`show` は、モードの系（`VibrationalSystem`）、読んだ入力（`FCEnvelopeInput`）、入力
ファイルのパスも受け、1 つだけ渡されればその結合の図を出す。CLI の `fcenvelope show` も
入力ファイルを受ける。**

## 決まりごと

- 系や入力から描けるのは結合の図だけなので、`--modes` / `modes=True` を付けなくても結合の
  図になる。付けてもよい。
- 系や入力は 1 つだけで渡す。結果と並べても重ね描きにはならないので、ほかと一緒に渡すと
  誤り（CLI では使用法エラー、終了コード 2）である。
- パスの見分け方: `.toml` は入力ファイルである。`.json` は結果ファイルと実効設定（入力、
  ADR-0065）のどちらでもありうるので、結果ファイルが必ず持つ `kind` の有無で分ける。
  `kind` を持たない JSON は入力として読み、入力としての誤りを報告する。
- 入力は `FCEnvelopeInput` として読み、`to_system()` で正準形の系にしてから描く。流儀・
  単位・CSV の参照（入力ファイルからの相対パス）の扱いは計算するときと同じである。
  入力ファイル全体を検証するので、計算に使えない入力は描く前に止まる。
- 描き方は結果の `--modes` と同じ `plot_modes` の既定（縦軸 g = √S、常に正）である。
- 組み合わせの確認は `plotting.check_shown` の 1 か所に置き、ライブラリと CLI が同じものを
  呼ぶ。結果どうしの組み合わせの規則は変えない。

## 理由

**`show` はライブラリの中で動くので、入力を読むことが二重実装にならない。** ADR-0083 が
作図スクリプトに入力ファイルを読ませなかったのは、`json` と `matplotlib` だけで動く
スクリプトに TOML・CSV・流儀と単位の換算を写すと `inputs.py` の二重実装になるからだった。
`show` は `FCEnvelopeInput` をそのまま使えるので、この理由は当てはまらない。

**モードの系は入力の時点で決まっている。** 結合の図は計算結果に依らない。入力を書いた
直後、計算する前に結合を確かめたい場面（CSV の列の並びや単位の取り違えを見る）でこそ
役に立つ。

**系を直接受けると、他のプログラムから使いやすい。** 外部の表から自分で
`VibrationalSystem` を組み立てたとき、`show(system)` で端末か窓に出せる。

## 検討した選択肢

- **結果だけを受けるまま（ADR-0084）**: 上の理由で退けた。一目見るための口なのに、
  そのために使わない計算を 1 回挟むことになる。
- **系や入力のときも `modes=True` を必須にする**: ほかに描けるものがないので、付け忘れを
  誤りにしても利用者の手間が増えるだけである。
- **`.json` を拡張子だけで結果ファイルとみなす**: 実効設定の JSON（ADR-0065, 0069）を
  渡したときに `unknown kind None` で止まり、入力であることが伝わらない。
- **作図スクリプト（`script --modes`）も入力ファイルを読む**: ADR-0083 の理由がそのまま
  残るので採らない。残す図が欲しければ、結果を作ってから `script --modes` で作る。
