# 作図スクリプトの中のファイル名はスクリプトの隣を指し、図の名前は描いたデータに追従する

- 日付: 2026-09-20
- 状態: 受理（ADR-0059 の「スクリプトからの相対で解決する」を利用者が書く名前まで広げ、
  ADR-0061 の画像の名前を引数で指したデータにも当てる）

ADR-0059 は生成ヘッダの位置を `Path(__file__).parent` 基準で書くと決め、ADR-0061 は
画像を `fcenvelope-<stem>.png` と名付けると決めた。どちらも**生成するときの話**で、
**利用者がスクリプトを使うときの話**が抜けていた。抜けた側の穴が 2 つ出た。

## 1. スクリプトの中に書いたファイル名

2 本目を重ねるときは、利用者がスクリプトの中にファイル名を書く。

```python
draw(ax, load("result_100K.json", KIND), label="100 K", color="C3")
```

`load` はこれをそのまま `Path` に渡していたので、**カレントディレクトリ**基準で開いた。
同じスクリプトの中で `DATA` はスクリプトの隣を指しているのに、利用者が書いた名前だけ
基準が違う。スクリプトの置き場所から起動すれば動き、別の場所から起動すると 1 本目は
読めて 2 本目だけ `FileNotFoundError` になる。基準が揃っていないので原因が分かりにくい。

**スクリプトの中に書いた相対パスは、スクリプトの隣として読む。** `beside()` を 1 つ
置き、`load` が最初に通す。ADR-0059 が「スクリプトと結果ファイルを一緒に移しても動く」
ために選んだ基準を、利用者が書く名前にも当てるだけである。

**コマンドラインの引数はカレントディレクトリ基準のままにする。** 引数はシェルが補完し、
シェルの規則で読まれることが利用者の期待だからである。`main` が `Path(...).absolute()`
で先に絶対パスへ直し、以降は `DATA` と同じに扱う。基準が 2 つあるのは変わらないが、
**どちらも 1 つの規則で言える**——引数はシェルの都合、スクリプトの中はスクリプトの都合。

## 2. 引数でほかのデータを指したときの図の名前

```bash
python result_plot.py result_0K.json
```

条件を振った結果に同じ設定を当てる、という使い方のために引数を受けている（ADR-0058）。
ところが `OUTPUT` は生成時に決まった 1 つの名前で埋め込まれているので、何を描いても
`fcenvelope-result.png` に書かれた。**見比べるために走らせるたびに、前の図が消える。**
引数を受ける目的と、書き出し先の決め方が噛み合っていなかった。

**画像の名前は、実際に描いたデータに追従させる。** `image_for()` を置き、既定の
データなら `OUTPUT`、引数でほかの結果を指したならその結果の隣に
`fcenvelope-<結果の名前>.png` を置く。名前の付け方は ADR-0061 のままで、当てる対象が
「生成時のデータ」から「描いたデータ」に広がっただけである。重ね描きでは
`fcenvelope-<エンベロープの名前>-overlay.png` とし、同じ結果を単独で描いた図と分ける。

既定のデータを描くときに `OUTPUT` を通すのは、**手で書き替えた `OUTPUT` を殺さない**
ためである。図の設定はすべてスクリプトの中にある（ADR-0057）という約束に、書き出し先も
含まれる。PNG の覚え書き（`Source`）も、生成時のデータ名ではなく実際に読んだデータ名を
書く。画像が単独で持ち出されたときに出どころが残る（ADR-0061）という目的は、名前が
中身と合っていて初めて果たされる。

## 検討した選択肢

- **`load` に基準を持たせず、文書の例を `DATA.parent / "..."` と書き換える**: 1 行で
  済むが、利用者が書く名前だけが長くなる。2 本目を足すのは「1 行増やすだけ」という
  ところが `draw` を外に出した理由（ADR-0058）なので、そこを重くしたくない。
- **引数もスクリプトの隣を基準にする**: 規則は 1 つになるが、シェルで補完した名前が
  開けない。引数は利用者がシェルに向かって書くものなので、シェルの規則から外せない。
- **図の名前を必ずデータから作り、`OUTPUT` を置かない**: 手で書き替える口が消える。
  図の設定はスクリプトの中にある（ADR-0057）という約束に反する。

## 帰結

`beside` は 3 つの雛形で同一の共有部分に入る（ADR-0059）。`image_for` は雛形ごとに
違う（単独の図はデータ 1 つ、重ね描きはエンベロープを見る）ので共有部分には入れない。
`test/test_emit.py` が見る共有部分の範囲が `def beside(` から `def image_for(` までに
なる。
