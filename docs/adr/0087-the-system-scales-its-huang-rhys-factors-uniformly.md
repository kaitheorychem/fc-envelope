# 系は全モードの S を一様に倍にした系を返せる

- 日付: 2026-10-01
- 状態: 受理

他のプログラムから読み込んだ結合を経験的に補正する、あるいは結合の強さだけを変えて
スペクトルの形を調べる、といった**物理的なモデル調整**のために、`VibrationalSystem` に
全モードの S を一様に倍にした新しい系を返すメソッドを足す。

```python
scaled = system.scale_huang_rhys(1.2)   # 全モードの S を 1.2 倍、振動数はそのまま
```

## 決まりごと

- **倍は正準量 S に掛かる。** 系が持つのは S だけなので（ADR-0003, 0044）、「結合を c 倍」の
  意味は流儀によって違う。g を c 倍すると S は c² 倍、λ を c 倍すると S は c 倍である。
  正準量で決めておけば意味が 1 つに定まり、どの流儀で考える人も換算できる（docstring に
  g と λ の場合を書く）。S を k 倍すると再配列エネルギー λ = Σ S_α ω_α もちょうど k 倍になる。
- **新しい系を返す。** 系は frozen なので元の系は変わらない。振動数は変えない。
- **倍は 0 以上の有限な数に限る。** 負の倍は、S が全部 0 で掛けても負にならない系でも
  `InvalidInputError` にする。結果の S ではなく倍そのものの誤りだからである。0 は許す
  （結合を切った基準として使える）。
- **ライブラリだけの口とする。** 入力ファイルにも CLI にも足さない。`--override` が
  `modes` を拒否する理由（ADR-0012）がそのまま残るためで、結果ファイルには倍を掛けた後の
  S しか残らず、倍そのものは記録されない。必要になれば別の ADR で決める。

## 理由

**可逆で失敗しない、正準形から正準形への写像だから系に置ける。** 新しい物理（ハミルトニアン
の変更）でも別の計算（ADR-0037 の対角化）でもない。状態を増やさないので、系を薄く保つという
ADR-0044 の方針とも矛盾しない。

**「全モード一様に」は系の性質である。** 1 モードだけなら `dataclasses.replace(mode, ...)`
で足りる。`VibrationalMode` に置くと、全モードに掛けるループは呼び出し側に残る。

**1 行で書けることでも、名前があると意図が読める。** これまでも
`VibrationalSystem([replace(m, huang_rhys=k * m.huang_rhys) for m in system.modes])` と
書けたが、何をしているかは読み解く必要があった。

## 検討した選択肢

- **単位の倍率で済ませる（ADR-0078）**: 有次元の流儀（λ, V）では `coupling_unit = [c, "eV"]`
  で一様に倍にできるが、これは単位や桁の取り違えを直す仕組みである。無次元の流儀
  （g, Δ, S）には単位を書けないので（`CouplingConvention.check_coupling_unit`）使えない。
  モデル調整を単位の欄に書くと、入力ファイルを読む人が単位の換算と取り違える。
- **流儀を引数に取り、g や λ のまま倍にする**: 換算は 1 行の算術で、流儀ごとの口を系に
  持たせるほどの重さがない。系は流儀を知らないという分担（ADR-0045）も崩れる。
- **自由関数にする（ADR-0011）**: ADR-0011 が自由関数にしたのは計算・保存・読み込み・描画
  で、結果クラスに責務を持たせないためである。系はすでに `reorganization_energy` や
  `occupations` を持っており、自分から導ける値を返す口はメソッドが自然である。

## 帰結

- 語彙として「S の一様倍」を CONTEXT.md に足す。単位の「倍率 (scale)」とは別物である。
- 出力ファイル・入力ファイル・CLI は変わらない。
