# 図の設定は生成した作図スクリプトに置き、入力ファイルにも CLI にも置かない

- 日付: 2026-09-18
- 状態: 受理

グラフ出力は「入力を読む・計算する・図を作る」の 3 段からなり、繰り返されるのは軽い
3 段目だけである。ところが調整できるつまみは CLI の 3 つ（`--title` / `--magnify` /
`--dpi`）しかなく、しかもシェルの履歴にしか残らなかった。実際の微調整で要るのは軸の
範囲・目盛り・色・凡例の位置・注釈・図の寸法といった果てのない量である。

**計算の出力に添えて作図スクリプトを生成し、図はそれを走らせて作る。** 図の設定は
matplotlib という既存の言語で書かれ、その言語の全機能が最初から使える。設定はファイル
として残り、同じデータに当て直せば同じ図が再現する。

境界は 1 行で言える。**入力ファイルは数を決める。作図スクリプトは絵を決める。**

| 何 | どこに書くか |
|---|---|
| モード・温度・σ・グリッド・選択条件 | 入力 JSON（形は変えない） |
| 軸の範囲・目盛り・色・凡例・表題・注釈・寸法・dpi・横軸の単位・出力先 | 作図スクリプト |

`grid` が入力側に残るのは、それが表示窓ではなく**標本する点そのもの**だからである。
スクリプトの `xlim` はグリッドの窓の内側を切り出す表示上の窓で、両者は別物である。

そのうえで規則を 1 つ立てる。**図のつまみを CLI に新しく足さない。**

## 検討した選択肢

- **CLI のオプションを増やす**: matplotlib の API を 1 対 1 で写すことになり終わりがない。
  しかも設定が実行後に残らないので、目的の半分を最初から満たせない。
- **入力 JSON に `plot` セクションを足す**: 同じ写像を pydantic のスキーマで行うことに
  なる。加えて入力は結果 JSON に正準形でエコーされる（ADR-0010）ので、計算をやり直して
  いないのに結果ファイルが変わる。`load → save` で不変という性質（ADR-0008）が図をいじる
  たびに揺さぶられる。
- **計算にフックして直接図を出す**（`--plot`）: 重い計算をやり直さないと図が変わらないの
  では、3 段に分けた意味がない。

## 帰結

入力ファイルの形は変わらないので `schema_version` は 2 に据え置く。入力は `modes` の
外部 CSV（ADR-0019）と作図スクリプトの両側から挟まれ、「計算の条件だけ」に痩せていく。

図の見た目が `plotting.py`（ライブラリ API、ADR-0011）と雛形の 2 か所に書かれることに
なる。`io` と `inputs` が `schema_version` を別々に持つのと同じ扱いで、一致はテストで
確かめる。
