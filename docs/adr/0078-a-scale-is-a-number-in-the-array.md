# 倍率は文字列に埋め込まず、配列の要素として数で書く

- 日付: 2026-09-24
- 状態: 受理（ADR-0076 の倍率の書き方と正式形の形を置き換える。正式名と別名の扱いは ADR-0076 のまま）

ADR-0076 は倍率を単位の文字列の先頭に置き、`"10^-4 a.u."` を空白で区切って読むと決めた。
これをやめ、倍率は**配列の要素として数で書く**。

```toml
[broadening]
sigma = [18.6, 0.001, "eV"]          # [値, 倍率, "単位"]

[grid]
unit = [0.001, "eV"]                 # 単位の欄は [倍率, "単位"]

[[modes]]
frequency = 500.0
coupling = [-0.3, 0.0001, "a.u."]    # 相手の出力の「10^-4 a.u.」
```

## 理由

有次元の値はすでに `[値, "単位"]` という配列で書いている（ADR-0072）。区切りを配列が
持っているのに、その 1 要素の中でさらに空白で区切るのは二重の仕組みである。倍率を配列の
要素にすれば、倍率は TOML / JSON の数として読まれ、文字列から数への変換（正規表現、
`10^k` の解釈、0 や負号や `nan` の弾き方）を自前で持たなくて済む。`10^-4` は書けなくなるが、
`1e-4` と `0.0001` は TOML でも JSON でも数としてそのまま書ける。

## 書き方

| 欄 | 倍率なし | 倍率あり |
|---|---|---|
| 単位の欄（`frequency_unit` / `coupling_unit` / `broadening.unit` / `grid.unit`） | `"eV"` | `[0.001, "eV"]` |
| 有次元の値 | `[18.6, "eV"]` | `[18.6, 0.001, "eV"]` |

- 倍率は数（整数か浮動小数点数）で、正の有限な値に限る。真偽値・文字列・0・負・`nan`・`inf`
  は誤りである。
- 単位の名前は文字列 1 つをそのまま名前として読む。空白で区切ったりはしないので、
  `"10^-4 a.u."` と書くと全体が未知の名前になり、受け付ける書き方
  （`"<name>"` または `[<scale>, "<name>"]`）を添えて報告される。
- 有次元の値の配列は 1〜3 要素である。3 要素のときは `[値, 倍率, "単位"]` の順だけを受ける。
- インラインテーブルは今までどおり受けない（ADR-0072）。

## 正式形

正式形は、倍率が無ければ正式名の文字列、あれば `(倍率, 正式名)` の組である。実効設定では
組は配列として書かれ、値に添えたものは `[値, 倍率, "正式名"]` に戻る。倍率は数として
書き出されるので、字面（`1e-4` か `0.0001` か）は JSON の書き出しの規則に従う。量として
同じ値なので、読み直せば同じ計算になる。冪等性（ADR-0076）は変わらない。

## 帰結

- `units.py`: 倍率の正規表現と文字列の切り分けを消す。`split_unit` は名前の文字列か
  `[倍率, 名前]` の組を受ける。単位の書き方の型 `UnitForm = str | tuple[float, str]` と、
  組み立てる `unit_form(scale, name)` を足す。`ResolvedUnit.text` は `ResolvedUnit.form`
  （`UnitForm`）になる。
- `inputs.py`: 単位の欄の型と `Quantity.unit` を `UnitForm` にする。有次元の値は 3 要素の
  配列を受け、`[値, 倍率, "単位"]` として読む。流儀が決める coupling の欄の置き換えも
  同じ形を扱う。
- 上位互換の追加なので `schema_version` は 3 のまま。`"10^-4 a.u."` の形は ADR-0076 の
  実装がリリースされる前に置き換わったので、互換は要らない。
