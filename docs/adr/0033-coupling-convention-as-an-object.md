# 振電相互作用の流儀を Enum + 関数表からオブジェクトへ昇格させる

- 日付: 2026-09-16
- 状態: 受理（ADR-0003 の実装形を改める。正準量を S とする決定自体は維持）

流儀レジストリの型が `dict[CouplingConvention, Callable[[float], float]]`、つまり coupling
値だけを受けて S を返す関数表だった。この型は `docs/theory/vcc.md` の 5 流儀のうち 2 つを
**構造的に表現できない**。

| 流儀 | S への変換 | ω が要るか | 単位 |
|---|---|---|---|
| g | S = g² | 不要 | 無次元 |
| Δ | S = Δ²/2 | 不要 | 無次元 |
| S | 恒等 | 不要 | 無次元 |
| **V** | S = V²/(2ħω³) | **必要** | エネルギー^(3/2) |
| **λ** | S = λ/(ħω) | **必要** | エネルギー |

そこで流儀を、変換式・単位の有無・振動数への依存の仕方を自分で知っているオブジェクトに
する。「この流儀は無次元なので `coupling_unit` の指定はエラー」「この流儀は frequency の
単位と組で解釈する」を型の中に書けるようにする。

## 検討した選択肢

- **変換関数の引数を広げるだけ**（coupling と frequency を受ける）: 変換式は表現できるが、
  **流儀ごとに単位の有無が違う**という事実を置く場所がない。
- **単位の層と流儀の層に分けた二段変換**: 2 層が直交する前提だが、V の ω³ がその前提を
  壊す（V を eV^1.5 で、ω を cm⁻¹ で与えてよいのか、という問いに層の分離では答えが出ない）。

流儀は 5 つで打ち止めである（物理モデルが固定なので増えない）ため、抽象を作りすぎる
リスクは小さい。
