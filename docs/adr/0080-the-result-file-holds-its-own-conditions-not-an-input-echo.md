# 結果ファイルは入力の写しではなく、計算に使った系と条件を自分の形で持つ

- 日付: 2026-09-24
- 状態: 受理（ADR-0010 の「入力エコー」を置き換える。単一 JSON から結果クラスを完全に
  復元する、流儀の曖昧さを残さない、は変わらない。ADR-0079 の「結果ファイルの形と版は
  変えない」を置き換える）

結果ファイルは `input` という名前で入力エコーを持ち、トップレベルの `frequency_unit` /
`coupling_convention` と `modes` の配列という、版 3 の入力ファイルと同じ形をしていた。
入力ファイルが版 4 で `[modes]` の形に変わると、エコーだけが古い入力の形で残り、結果
ファイルを開いた人が見る入力の形と、実際に書く入力の形が食い違った。エコーを入力の形に
揃え直すと、今度は入力の書き方が変わるたびに結果ファイルの形と版、生成済みの作図
スクリプトまで追従することになる。

実行した設定そのものは、入力ファイルと同じ形の実効設定（`*_config.json`、ADR-0065）が
すでに持っている。結果ファイルが持つ必要があるのは、結果を読むのに要る値、すなわち
**計算に使った系と条件**だけである。

**結果ファイルは `input` の代わりに `conditions` を持つ。形は結果ファイル側で決め、
入力ファイルの形には合わせない。**

```json
"conditions": {
  "modes": [{ "frequency": 1200.0, "huang_rhys": 0.25 }],
  "temperature": 300.0,
  "broadening": { "sigma": 150.0 },
  "grid": { "e_min": -4000.0, "e_max": 1000.0, "de": 5.0, "n_fft": 2048 }
}
```

## 決まりごと

- モードは `frequency` と `huang_rhys` で書く。S をキーの名前で持つので、流儀の欄は
  要らない。振動数を含むエネルギーはヘッダの `energy_unit`（`cm^-1`）で書く。
- `conditions` には単位・流儀・既定の単位の欄を置かない。入力ファイルにしかない語彙
  （`coupling_convention` / `frequency_unit` / `coupling_unit` / `rows` / `csv` /
  `grid.points` など）は持ち込まない。
- `grid` は入力の指定（`grid.points`）ではなく、解決済みの全域グリッド
  （`de` / `n_fft`、ADR-0070）を書く。
- `run` の結果は `temperature` / `broadening` / `grid`、`lines` の結果は `temperature` /
  `selection` を持つ（今までと同じ）。

## 理由

実効設定では代わりにならない。実効設定は `--no-config` で書かれないことがあり、別の
ファイルである。値は利用者の単位・流儀のままで、読むには `io` が `inputs` に頼ることに
なる（ADR-0041）。解決済みのグリッドも持たない。したがって結果ファイルは、結果を読むのに
要る値を自分で持ち続ける。

そのうえで形を入力に合わせないのは、両者の変わる理由が違うためである。入力ファイルは
人が書きやすいように変わる（単位の添え方、CSV の列、ブロックの置き場）。結果ファイルの
中身は、計算が何を使ったかが変わったときにしか変わらない。

## 帰結

- 結果ファイルの `schema_version` を 4 へ上げる。入力ファイルの版とは別に数え、入力の
  書き方が変わっても上げない（`io.SCHEMA_VERSION` の注記）。今はたまたまどちらも 4 である。
- 版 3 の結果ファイルは `SchemaVersionError` になる。互換層は置かない（まだ実運用に
  載せていない）。生成済みの作図スクリプト（ADR-0060 により上書きされない）は版 4 の結果
  ファイルを読まないので、`fcenvelope script` で作り直す。
- 作図スクリプトの雛形は `data["conditions"]` から温度と σ を読み、overlay は二つの
  ファイルの `conditions.modes` を比べる。
- 用語「入力エコー」は使わず、「計算条件 (conditions)」と呼ぶ。
