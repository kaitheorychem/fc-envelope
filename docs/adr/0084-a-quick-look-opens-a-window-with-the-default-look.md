# 一目見るための口として、既定の見た目で窓に出す show を CLI とライブラリに置く

- 日付: 2026-09-29
- 状態: 受理（ADR-0057 の「図のつまみを CLI に足さない」と ADR-0061 の作図スクリプトの
  出力先はそのまま。ADR-0061 で退けた「`plot` を一目見る用に残す」を、つまみを持たない形で
  改めて置く）

正式に採用する図は、微調整のために作図スクリプトで作る（ADR-0057, 0061）。この方針は変えない。
ただ、調整するつもりのない結果をちょっと確かめたいだけでも、スクリプトを書き出して走らせる
2 手が要り、ファイルが 1 本と画像が 1 枚増える。端末表示は kitty graphics protocol に対応した
端末でしか出ない。ほかのプログラムに組み込んで使う場合も、ライブラリの `plot_*` は `Figure`
を返すだけなので、一目見るには呼び出し側が `plt.show()` と組み合わせ方を知っている必要があった。

**保存済みの結果を既定の見た目で描いて `plt.show()` の窓に出す口を、CLI の
`fcenvelope show RESULT.json...` とライブラリの `fcenvelope.show(...)` に置く。**

## 決まりごと

- 取る結果の組み合わせは `fcenvelope script` と同じ。1 つならその種類の図
  （`plot_any`）、エンベロープと線リストを 1 つずつなら重ね描き（`plot_overlay`、順序は
  問わない）、`--modes` / `modes=True` なら結合の図（`plot_modes`、結果は 1 つ）。
  CLI での組み合わせの誤りは `script` と同じ使用法エラー（終了コード 2）になる。
- 見た目は `plot_*` の既定のまま。**つまみは持たない。** 表題・倍率・縦軸の量などを
  変えたいなら、ライブラリでは `plot_*` の引数を使い、CLI では `script` でスクリプトを作る。
- `show` は何も書き出さない。作図スクリプトも画像も作らない。
- ライブラリの `show` は計算した結果そのものと結果ファイルのパスのどちらも受ける。
  `block` は `plt.show` にそのまま渡し、描いた `Figure` を返す。
- CLI の `show` は、matplotlib のバックエンドが窓を開けないもの（画面がないときに自動で
  落ちる `agg` など）なら、何も出さずに 0 で終わる代わりに終了コード 1 で止まり、`script` と
  `MPLBACKEND` を案内する。ライブラリの `show` はこの判定をしない。バックエンドを選ぶのは
  組み込む側のアプリケーションで、matplotlib 自身の警告で足りる。

## 理由

**計算にはフックしない。** `run --show` のように計算と同時に出すと、見直すたびに計算を
やり直すことになる（ADR-0057 で `--plot` を退けたのと同じ理由）。結果ファイルを読むので、
計算・保存・描画の 3 段は分かれたままである。

**つまみを持たないので、調整の置き場が二股にならない。** ADR-0061 が `plot` を残さなかった
理由は「どちらで調整するかが二股になる」ことだった。`show` は既定の見た目しか出さないので、
調整したくなった時点で行き先は作図スクリプトに決まっている。描画の実装も `plot_*` の 1 系統
のままで、`show` はその組み合わせを選んで `plt.show()` を呼ぶだけである。

**ライブラリにも同じ口を置く。** ほかのプログラムに組み込むとき、組み合わせの規則を
呼び出し側に写さずに済む。CLI の `show` はこの関数を呼ぶだけにして、規則を 1 か所に保つ。

## 検討した選択肢

- **`run` / `lines` に `--show` を足す**: 上の理由で退けた。計算の直後に見たいなら
  `run` の後に `show` を続ければよい。
- **作図スクリプトに窓で出す出力先を足す**: スクリプトは調整して残すためのもので、一目見る
  だけのためにファイルを作る 2 手は減らない。
- **`show` に表題や倍率のつまみを持たせる**: ADR-0057 の「図のつまみを CLI に足さない」に
  反し、調整の置き場が二股になる。
