# 返す線は線強度の絶対閾値だけで選ぶ

- 日付: 2026-09-16
- 状態: 受理（`min_intensity` の呼称は ADR-0032 が改める）

全遷移は無限個あるので返す線を選ぶ基準が要る。**線強度の絶対閾値 `min_intensity` を唯一の主たるつまみ**とし、これ以上の線をすべて返す。

1 モードあたりの寄与 P(n)FC_mn は 1 以下なので、完成した線の強度は途中経過の積を超えない。したがってモードを 1 つずつ合成しながら閾値で枝刈りしても、閾値以上の線を取りこぼさない。さらに未処理のモードが到達しうる重みの積の上限（suffix_bound）を掛けて枝刈りすることで、途中経過の本数を抑えたまま網羅性を保つ。モードごとの選択は独立なので suffix_bound[0] は**最強の線の強度そのもの**になる。

## 検討した選択肢

「最強の線の何分の 1 まで」という**相対閾値は採らない**。絶対閾値なら `captured_intensity`（拾えた強度の総和）がそのまま「スペクトルのどれだけを見ているか」を意味し、エンベロープとの突き合わせにも直結する。つまみを 2 つ持つより、1 つの意味が明確なつまみと警告文で十分と判断した。

同じ理由で、強度上位 N 本だけを取る指定も、線のエネルギー窓による絞り込みも設けない。`max_lines` は上限であって順位指定ではなく、窓が要るなら呼び出し側で濾せる。

## 帰結

熱的に活性なモードが多いと、強度が膨大な数の線に分散して 1 本も閾値に届かなくなる。これは実装の不足ではなく、**離散線による記述がその系で意味を失っている**ということであり、理論文書が「スペクトル全体にはフーリエ変換が重要」と言う所以でもある。空の結果と最強の線の強度を返し、警告でそう伝える。
