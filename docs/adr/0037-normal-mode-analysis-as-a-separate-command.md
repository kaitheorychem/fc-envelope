# 正規モード分解を別コマンドに分け、パーサに入れない

- 日付: 2026-09-16
- 状態: 受理

非対角項を含む基底で振動数と結合を与える入力形式を将来足す。これはハミルトニアンを
変えないので「入力の与え方の拡張」だが、**対角化をパーサの中で行わない**。
`fcenvelope diagonalize` という別コマンドとし、その出力である modes CSV を既存の
`{"path": ...}` 参照（ADR-0019）で読む。

理由は、**対角化が「入力の解釈」ではなく「別の計算」**だからである。単位変換や流儀変換は
情報を失わない可逆な写像だが、対角化は数値計算であり、失敗しうるし（負の固有値＝虚振動を
どう扱うか）、診断値を持つべきものである。これを pydantic の validator に押し込むと、
「入力のパースに失敗した」のか「対角化が物理的に破綻した」のかが例外の型で区別できなく
なる。`to_modes()` の「流儀を消費して正準化する」という契約は、可逆で失敗しない変換だから
成立している。

## 帰結

出力は現行のモード表 CSV とし、`modes` の参照形態は増やさない。ADR-0020 が CSV のコメント
行を禁じているため来歴は CSV に載らないが、検討の結果、失われる情報は実用上ほぼない。
虚振動は `frequency > 0` の制約により黙って通り抜けられず、縮退は同値の行として見え、
質量重みの規約は無次元の S に変換された時点で消費される。

ただし**並進・回転の 6 自由度を落とす閾値だけは、出力 CSV から復元できない**。低振動数
モードは熱占有が大きく（300 K で 15 cm⁻¹ なら n ≈ 13.4、1200 cm⁻¹ なら n ≈ 0.003）、境界
付近の 1 本を入れるか落とすかでエンベロープの幅が目に見えて変わる。したがってこの閾値は
既定値を置かず引数で明示必須とし、`temperature` に既定値を置かなかったのと同じ扱い
（ADR-0021）にする。
