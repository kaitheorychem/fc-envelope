# 機械的な重複だけを除去し、診断メッセージは手書きで残す

- 日付: 2026-09-16
- 状態: 受理

`io.py` の `result_to_dict` / `fc_lines_to_dict`、`result_from_dict` / `fc_lines_from_dict` は
同じ骨格（`schema_version` 検査 → `kind` 検査 → 単位検査 → 入力エコー → `derived` →
`diagnostics` → ペイロード）を 2 回書いており、さらに `_DIAGNOSTIC_FLOAT_FIELDS` のような
フィールド名タプルを dataclass から手で複製していた。

**機械的な重複と、見かけだけの重複を区別する。**

- **真の重複なので消す**: フィールド名タプルは `dataclasses.fields()` から導出する（dataclass に
  フィールドを足してタプルに足し忘れれば静かに壊れる）。共通ヘッダの読み書きも 1 箇所に
  まとめる。
- **見かけだけなので残す**: 2 つの `_quality_messages` は構造こそ似ているが、閾値の向きも型も
  違い（float の大小、bool の真、`abs(1−x) >= min_weight` という動的閾値）、**メッセージ本文が
  すべて違う**。本文は「何が起きたか」に加えて「どう直すか」（`de` を σ/2 より小さく、
  `e_min`/`e_max` を広げる、`max_quanta` を上げる…）というその項目にしかない知識を持つ。

## 検討した選択肢

各診断項目が閾値とメッセージ雛形を自分で持つ宣言的な検査機構を検討したが採らない。8 項目
× 2 系統という規模に対して機構が重く、しかも**雛形に押し込めると診断機能の一番の価値
（具体的な直し方）が失われる**。
