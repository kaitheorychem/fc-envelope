# 単位変換は入力の境界で行い、正準単位へ畳んでから計算に渡す

- 日付: 2026-09-17
- 状態: 受理（ADR-0002 の「検証点を変換点に差し替える」を実行する。単位の名前の扱い（正式名・別名・倍率）は ADR-0076 が補う）

ADR-0002 は単位を `cm^-1` に固定し、「将来変換を入れるときは検証点を変換点に差し替える
だけで済む」ように単位を保持・検証する場所だけを確保していた。その差し替えを行う。

変換は**入力ファイルの型（`inputs.py`）の中だけ**で起こる。`to_system()` / `to_broadening()`
/ `to_grid()` が単位と流儀を消費し、計算用の値の型（`models.py`）には常に正準形が渡る
（ADR-0045）。計算・結果・描画は引き続き単位を知らない。

## 対応する単位

初版で受け付けるエネルギー単位は次のとおり。追加は変換表への 1 行で済む。

| 名前 | 備考 |
|---|---|
| `cm^-1` | 正準単位。既定値 |
| `eV` | |
| `hartree` | 原子単位 |
| `THz` | 振動数だが、ε = h·ν としてエネルギーに読む |
| `kJ/mol` | |
| `kcal/mol` | |

波長（`nm`）は入れない。エネルギーとの関係が逆数なので、等間隔のエネルギーグリッドを
波長で指定できず（ADR-0006 の「明示的なエネルギーグリッド」が崩れる）、軸ごとに意味が
変わってしまう。必要になったら描画の横軸の側で扱う。

変換係数は `scipy.constants` から導出し、自前の数値定数表は持たない。ADR-0016 が scipy を
「将来の単位変換の受け皿」として必須依存に入れているので、新しい依存は足さない。pint 等の
単位ライブラリも導入しない（ADR-0002）。

未対応の単位は従来どおり `UnsupportedUnitError` で拒否する。

## 帰結

`check_frequency_unit()` は「正準単位であることを確かめて返す」関数から「任意の単位を
正準単位へ換算する係数を引く」関数に変わる。同じ変換表を σ・グリッド・coupling が共有する。
coupling だけは次元がエネルギーの整数乗とは限らないため、係数を `energy_power` 乗して使う
（ADR-0055 の範囲で）。

CLI は変更が要らない。上書きの値は入力ファイルと同じ単位で読み、入力ファイルの型に適用して
から正準化する経路が既に通っている（ADR-0050、実装済み）。

出力側も変更が要らない。結果ファイルの入力エコーは常に正準形で書き、読み込み時に `cm^-1`
以外を拒否する（ADR-0010）。単位変換は入力ファイルを読む向きにしか存在しない。
