# 値の範囲は、計算用の値の型が自分で検証する

- 日付: 2026-09-17
- 状態: 受理

ADR-0045 で計算用の値を frozen dataclass にしたため、`Broadening(sigma=-1.0)` のような
不正な値を誰が止めるかを決める必要がある。値の型が `__post_init__` で自分の不変条件
（σ > 0、e_min < e_max など）を検証し、違反は `InvalidInputError` にする。入力ファイルの
型（pydantic）が扱うのは、ファイルの構造・単位・流儀の検査だけにする。

「σ > 0」や「e_min < e_max」は計算用の値そのものが守るべき条件である。入口が入力ファイル
でもライブラリの直接呼び出しでも、同じように守られるべきである。README でも
`compute_envelope` を直接呼ぶ使い方を案内している。

## 検討した選択肢

- **入力ファイル側だけで検証する**案では、ライブラリから直接呼んだときに不正な値が計算まで
  届く。
- **両方で同じ制約を書く**案では、制約を変えたときに 2 箇所を直す必要が生まれる。

## 帰結

pydantic が自動で付けていた、フィールドの位置付きのエラーメッセージは自前で添える。
入力ファイルの型から値の型を作る箇所は 1 つなので、そこで一度書けば済む。
