# 一目見るための口として、既定の見た目で端末か窓に出す show を CLI とライブラリに置く

- 日付: 2026-09-29
- 状態: 受理（ADR-0057 の「図のつまみを CLI に足さない」と ADR-0061 の作図スクリプトの
  出力先はそのまま。ADR-0061 で退けた「`plot` を一目見る用に残す」を、つまみを持たない形で
  改めて置く）

正式に採用する図は、微調整のために作図スクリプトで作る（ADR-0057, 0061）。この方針は変えない。
ただ、調整するつもりのない結果をちょっと確かめたいだけでも、スクリプトを書き出して走らせる
2 手が要り、ファイルが 1 本と画像が 1 枚増える。端末表示は kitty graphics protocol に対応した
端末でしか出ない。ほかのプログラムに組み込んで使う場合も、ライブラリの `plot_*` は `Figure`
を返すだけなので、一目見るには呼び出し側が `plt.show()` と組み合わせ方を知っている必要があった。

**保存済みの結果を既定の見た目で描いて一目見る口を、CLI の `fcenvelope show RESULT.json...`
とライブラリの `fcenvelope.show(...)` に置く。出し先は、端末が kitty graphics protocol に
対応していれば端末、そうでなければ `plt.show()` の窓である。**

## 決まりごと

- 取る結果の組み合わせは `fcenvelope script` と同じ。1 つならその種類の図
  （`plot_any`）、エンベロープと線リストを 1 つずつなら重ね描き（`plot_overlay`、順序は
  問わない）、`--modes` / `modes=True` なら結合の図（`plot_modes`、結果は 1 つ）。
  CLI での組み合わせの誤りは `script` と同じ使用法エラー（終了コード 2）になる。
- 見た目は `plot_*` の既定のまま。**つまみは持たない。** 表題・倍率・縦軸の量などを
  変えたいなら、ライブラリでは `plot_*` の引数を使い、CLI では `script` でスクリプトを作る。
- `show` は何も書き出さない。作図スクリプトも画像も作らない。
- ライブラリの `show` は計算した結果そのものと結果ファイルのパスのどちらも受ける。
  `block` は `plt.show` にそのまま渡し、描いた `Figure` を返す。
- **端末が画像を出せるなら端末を優先する。** 判定は端末に尋ねて行う。1x1 画素の画像を
  検証だけさせる問い合わせ（`a=q`）の後ろに、どの端末も答える DA1 を続けて送り、DA1 の
  答えより先に画像の答えが来れば対応している。0.5 秒待って何も来なければ非対応とみなす。
  標準入出力のどちらかが端末でなければ尋ねない。端末への出し方（画素幅から解像度を逆算
  する、4096 バイトずつのチャンク）は作図スクリプトの `show` と同じ（ADR-0061）。
- 判定は CLI では `--terminal` / `--window`、ライブラリでは `terminal=True` / `False` で
  固定できる。tmux 越しのように答えないが画像は通す端末や、kitty の中でも拡大できる窓で
  見たい場合のためである。これは出し先の選択で、図のつまみではない。
- 端末に出した図は pyplot から外す。後で `plt.show()` を呼んだときに窓でもう一度出て
  こないようにするためで、返した `Figure` は保存などにそのまま使える。
- CLI の `show` は、端末に出せず、matplotlib のバックエンドも窓を開けないもの（画面が
  ないときに自動で落ちる `agg` など）なら、何も出さずに 0 で終わる代わりに終了コード 1 で
  止まり、`script`・`--terminal`・`MPLBACKEND` を案内する。ライブラリの `show` はこの判定を
  しない。バックエンドを選ぶのは組み込む側のアプリケーションで、matplotlib 自身の警告で
  足りる。

## 理由

**計算にはフックしない。** `run --show` のように計算と同時に出すと、見直すたびに計算を
やり直すことになる（ADR-0057 で `--plot` を退けたのと同じ理由）。結果ファイルを読むので、
計算・保存・描画の 3 段は分かれたままである。

**つまみを持たないので、調整の置き場が二股にならない。** ADR-0061 が `plot` を残さなかった
理由は「どちらで調整するかが二股になる」ことだった。`show` は既定の見た目しか出さないので、
調整したくなった時点で行き先は作図スクリプトに決まっている。描画の実装も `plot_*` の 1 系統
のままで、`show` はその組み合わせを選んで `plt.show()` を呼ぶだけである。

**端末を優先し、判定は尋ねて行う。** この計算は SSH の先の計算機で走らせることが多く、
そこでは窓が開けないが、手元の端末が kitty（や同じ protocol に対応した WezTerm、Ghostty）
なら画像は届く。作図スクリプトと同じ出方になるので、どちらで見ても同じに見える。ただし
作図スクリプトのように「標準出力が端末なら出す」（ADR-0061）では足りない。スクリプトは
画像ファイルを必ず残すので、非対応の端末でエスケープ列が素通りしても実害が小さいが、
`show` は何も残さないうえ、端末に出せないなら窓に回したい。そのため対応しているかを
実際に尋ねる。環境変数（`TERM`、`KITTY_WINDOW_ID`）は SSH を越えると当てにならず、
kitty 以外の対応端末も拾えないので使わない。

端末への出し方はライブラリと作図スクリプトの 2 か所に書かれる。スクリプトは
`fcenvelope` を import しない（ADR-0058）ので 1 つにまとめられない。解像度の定数の一致は
テストで確かめる（ADR-0057 と同じ扱い）。

**ライブラリにも同じ口を置く。** ほかのプログラムに組み込むとき、組み合わせの規則を
呼び出し側に写さずに済む。CLI の `show` はこの関数を呼ぶだけにして、規則を 1 か所に保つ。

## 検討した選択肢

- **`run` / `lines` に `--show` を足す**: 上の理由で退けた。計算の直後に見たいなら
  `run` の後に `show` を続ければよい。
- **CLI では常に窓、端末は作図スクリプトだけ**: 窓の開けない SSH の先で `show` が使えず、
  一目見る口として役に立つ場面がいちばん多いところを落とす。
- **作図スクリプトと同じく、標準出力が端末かどうかだけで端末に出す**: 上の理由で退けた。
- **作図スクリプトに窓で出す出力先を足す**: スクリプトは調整して残すためのもので、一目見る
  だけのためにファイルを作る 2 手は減らない。
- **`show` に表題や倍率のつまみを持たせる**: ADR-0057 の「図のつまみを CLI に足さない」に
  反し、調整の置き場が二股になる。
