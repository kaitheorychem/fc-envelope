# CSV の書式は RFC 4180 に厳密に従い、独自拡張をしない

- 日付: 2026-09-15
- 状態: 受理

CSV の方言を自前で増やさず、RFC 4180 をそのまま採る。区切りはカンマ、引用符付きフィールド可、改行は CRLF / LF のどちらも可、最終行末の改行は任意。文字コードは UTF-8（BOM は文字コード層の問題として許容する。Excel 出力対策）。

列は **`frequency` と `coupling` の 2 列のみ**。ヘッダは RFC 4180 と同じく省略可で、1 行目がちょうどこの 2 列の組（順序は問わない）ならヘッダ、そうでなければ `frequency, coupling` の順のデータ行とみなす。列名は数値にならないのでこの判定は曖昧にならない。

## 検討した選択肢

- **コメント行は受け付けない**。RFC 4180 にコメントの規定がないため、`#` で始まる行も通常のレコードとして扱う。W3C の CSV on the Web は `commentPrefix` を持つが、これはメタデータ側で方言を宣言する仕組みであり CSV 自体の仕様ではないので採らない。
- **空行は「空のレコード」**であり、列数不一致としてエラーにする。
- **フィールド前後の空白はフィールドの一部**。したがって `frequency, coupling` はヘッダと認識されず、データ行として数値変換に失敗しエラーになる。
- **`index` / `label` / `symmetry` などの補助列は受け付けない**。読み飛ばすと「意味のある列」と誤解されやすく、しかも何も検証されない。必要になった時点で、意味と検証（一意性など）を決めて追加する。
- **行の重複は検出しない**。縮重モードは振動数・coupling とも同値の行が正当に複数並ぶため。行の順序は計算結果に影響しない。

エラーは `InvalidInputError` に `ファイル名:行番号` を添える。1 行目がヘッダでもデータ行でもない場合は「ヘッダを書くならこの 2 列ちょうど」という案内を添える。
