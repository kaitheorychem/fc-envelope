# 図の設定を作図スクリプトに追い出す

- 状態: 検討中（受理したら ADR と作業計画に分ける。まだ何も実装していない）
- 関係する既存の決定: ADR-0005, 0010, 0012, 0027, 0028, 0030, 0047, 0049, 0052, 0053

## 解こうとしていること

グラフ出力の作業は 3 段からなる。

| 段 | 何をするか | 重さ | 繰り返す頻度 |
|---|---|---|---|
| 1 | 入力ファイルを読む | 軽い | 条件を変えたとき |
| 2 | 計算してデータを作る | **重い** | 条件を変えたとき |
| 3 | データから図を作る | 軽い | **微調整のたび何度でも** |

3 だけを繰り返す運用が本来の姿である。加えて、3 の生成物である画像ファイルは単独で
持ち出されがちで、メタ情報を書き込みにくい。だから**図の設定はプログラムの側に残って
いてほしい**——実行後に読み返せて、同じデータに当てれば同じ図が出る形で。

現状の `fcenvelope plot` はすでに「2 をやり直さずに 3 だけ」を満たしているが、調整できる
のが `--title` / `--magnify` / `--dpi` の 3 つしかなく、しかもその 3 つはシェルの履歴に
しか残らない。実際の微調整で要るのは、軸の範囲・目盛り・色・線幅・凡例の位置・注釈・
図の寸法・複数条件の重ね方といった果てのない量で、これを増やす先は 2 つしかない。

- **CLI のオプションに足す**: matplotlib の API を 1 対 1 でオプションに写すことになり、
  終わりがない。しかも実行後に残らない。
- **入力 JSON に `plot` セクションを足す**: 同じ写像を pydantic のスキーマで行うことに
  なる。入力ファイルは「どの分子をどの条件で計算したか」の記録なのに、図の見た目が
  混ざると、計算をやり直さない変更のたびに入力ファイルが書き換わる。

どちらも採らない。代わりに、**2 の出力に添えて 3 のための作図スクリプトを生成し、3 では
それを独立したプログラムとして走らせる**。図の設定は matplotlib という既存の言語で書かれ、
その言語の全機能が最初から使える。設定はファイルとして残り、同じデータに当て直せば
同じ図が再現する。

## 境界の引き方

新しい規則は 1 行で言える。

> **入力ファイルは数を決める。作図スクリプトは絵を決める。**

| 何 | どこに書くか | 変えたら何が起きるか |
|---|---|---|
| モード・温度・σ・グリッド・選択条件 | 入力 JSON（現状のまま） | 2 をやり直す必要がある |
| 軸の範囲・目盛り・色・凡例・表題・注釈・図の寸法・dpi・横軸の単位 | 生成された作図スクリプト | 3 をやり直すだけでよい |

`grid` が入力側に残るのは、それが「表示窓」ではなく**標本する点そのもの**だからである。
作図スクリプトの `xlim` は grid の窓の内側を切り出す表示上の窓で、両者は別物である。
グリッドの外を見たければ 2 をやり直すしかない、という関係が境界と一致する。

この境界は、`interface.md` の「将来の拡張」に未決として残っている**描画の横軸の単位**にも
答えを出す。CLI オプションでも入力ファイルでもなく、作図スクリプトの中の定数になる。

## ワークフロー

```bash
# 1 + 2: 読み込みと計算。重いのはここだけ
uv run fcenvelope run input.json -o result.json --script
#   -> result.json       計算結果（現状のまま）
#   -> result_plot.py    作図スクリプト（新規）

# 3: 描画。ここを何度でも繰り返す
python result_plot.py            # -> result_plot.png
vi result_plot.py                # 軸・色・注釈を直す
python result_plot.py            # すぐ出る
```

条件を変えて 2 をやり直しても、**調整済みのスクリプトは上書きされない**（後述）。

```bash
uv run fcenvelope run input.json -o result.json --sigma 80 --script
#   -> result.json を更新、result_plot.py はそのまま
python result_plot.py            # 同じ設定で新しいデータを描く
```

重ね描きは 2 つの結果が要るので、結果が出そろってから生成する。引数の形は今の
`plot` と同じ（エンベロープ 1 つと線リスト 1 つ、順序は任意。ADR-0030 の規則をそのまま
移す）。

```bash
uv run fcenvelope run   input.json -o env.json
uv run fcenvelope lines input.json -o lin.json
uv run fcenvelope script env.json lin.json -o overlay_plot.py
python overlay_plot.py
```

温度を振った比較のように、CLI が受け付けない枚数の重ね描きも、スクリプトを手で
足すだけでできるようになる。今の `plot` が「1 つか、エンベロープ 1 + 線 1」しか
取れないのは CLI の都合であって、図の都合ではない。

## 生成される作図スクリプト

### 満たすべき条件

| 条件 | なぜ |
|---|---|
| 単独で動く（`json` + `matplotlib` だけ。`fcenvelope` を import しない） | 環境やパッケージ版に縛られない。中身を読めば何を描いているか全部分かる |
| 図の設定はすべてスクリプトの中に literal で書かれている | 実行後に読み返せる。これが目的そのもの |
| データは実行時に結果ファイルから読む | 同じスクリプトを新しいデータに当てられる |
| 既存のスクリプトを勝手に壊さない | 調整の成果はスクリプトの側にしかない |
| 描画の中身は `draw(ax, data)` に閉じている | notebook から import できる。既定の見た目を試験で留められる |
| 画像にメタ情報を焼く | 画像が単独で持ち出されても出どころが残る |

### 例（エンベロープ）

```python
#!/usr/bin/env python3
"""Franck-Condon envelope -- figure script generated by fcenvelope 0.1.0.

Data: result.json (fcenvelope.envelope, computed 2026-09-17T03:21:44Z)
Run:  python result_plot.py [DATA.json]

This file is yours. fcenvelope never reads it back; edit anything below.
"""

from __future__ import annotations

import json
import sys
from pathlib import Path

import matplotlib.pyplot as plt

# --- generated header (fcenvelope) ---------------------------------------
DATA = Path(__file__).with_name("result.json")
OUTPUT = Path(__file__).with_name("result_plot.png")
KIND = "fcenvelope.envelope"
SCHEMA_VERSION = 2
# --- end generated header ------------------------------------------------

# 図の設定。ここから下はすべて手で変えてよい。
FIGSIZE = (7.0, 4.2)
DPI = 150
TITLE = None
LABEL = None
COLOR = "C0"
LINEWIDTH = 1.2
XLIM = None          # None ならデータの窓いっぱい。(-3000.0, 500.0) のように書ける
YLIM = None
GUIDE = {"color": "0.7", "linewidth": 0.8, "zorder": 0}

# 横軸の単位。計算は常に cm^-1 で行われているので、ここは表示の掛け算だけ。
# 縦軸の密度は 1/(横軸の単位) なので、割って ∫F dE = 1 を保つ。
#   eV にするなら  X_UNIT, X_SCALE = "eV", 1.0 / 8065.543937
X_UNIT = "cm$^{-1}$"
X_SCALE = 1.0


def load(path: Path | str, kind: str) -> dict:
    data = json.loads(Path(path).read_text(encoding="utf-8"))
    if data.get("kind") != kind or data.get("schema_version") != SCHEMA_VERSION:
        raise SystemExit(
            f"{path}: expected {kind} (schema {SCHEMA_VERSION}), got "
            f"{data.get('kind')!r} (schema {data.get('schema_version')!r})"
        )
    return data


def draw(ax, data: dict, *, label: str | None = LABEL, color: str = COLOR) -> None:
    """F(E) を 1 枚の軸に描く。図の中身はここだけ。"""
    energy = [e * X_SCALE for e in data["spectrum"]["energy"]]
    density = [d / X_SCALE for d in data["spectrum"]["density"]]

    ax.plot(energy, density, color=color, linewidth=LINEWIDTH, label=label)
    ax.axvline(0.0, **GUIDE)            # E = 0 は ZPL
    ax.set_xlabel(f"$E$ / {X_UNIT}")
    ax.set_ylabel(f"$F(E)$ / 1/{X_UNIT}")
    ax.margins(x=0.0)


def main() -> None:
    data = load(sys.argv[1] if len(sys.argv) > 1 else DATA, KIND)

    fig, ax = plt.subplots(figsize=FIGSIZE, layout="constrained")
    draw(ax, data)

    # 2 本目を重ねるとき（温度を振った比較など）:
    # draw(ax, load("result_100K.json", KIND), label="100 K", color="C3")

    if TITLE is not None:
        ax.set_title(TITLE)
    if XLIM is not None:
        ax.set_xlim(*XLIM)
    if YLIM is not None:
        ax.set_ylim(*YLIM)
    if ax.get_legend_handles_labels()[1]:
        ax.legend()

    fig.savefig(
        OUTPUT,
        dpi=DPI,
        metadata={
            "Software": f"fcenvelope {data['fcenvelope_version']}",
            "Source": f"{Path(DATA).name} ({data['created_at']})",
            "Description": f"T = {data['input']['temperature']:g} K, "
                           f"sigma = {data['input']['broadening']['sigma']:g} cm^-1",
        },
    )
    print(f"wrote {OUTPUT}")


if __name__ == "__main__":
    main()
```

読み方の要点。

- **生成ヘッダ**は再生成のときに差し替わる唯一の範囲で、マーカーで囲ってある。ここから
  下は生成側が二度と触らない。
- `DATA` / `OUTPUT` はスクリプトからの相対で解決する。スクリプトと結果ファイルを
  一緒に移しても動く。`sys.argv[1]` で別のデータに当てられるのは、条件を振った比較の
  ためである。
- `kind` と `schema_version` の確認が入っているのは、結果ファイルの形式が変わったときに
  `KeyError` ではなく読める文言で止めるため。生成されたスクリプトは利用者の手元に
  残り続けるので、その版ずれは必ず起きる。
- **PNG のメタ情報**（`Software` / `Source` / `Description`）を既定で焼く。画像が単独で
  持ち出されがちだという問題への、スクリプト側からの直接の答えになる。

この例は実際に `fcenvelope run` の結果へ当てて動かしてある。図は `plot_envelope` が
描くものと同じで、別の種類のファイルを渡すと上の文言で止まり、焼いたメタ情報は
画像から読み出せる。

### 重ね描きの雛形

重ね描きのスクリプトには、`plotting.plot_overlay` が持っている知識（ADR-0027）を
数式のまま展開して書く。ここを生成物に書き下せることが、利用者が手で書き起こす場合との
最大の差になる。

```python
MAGNIFY = 1.0        # 棒だけを拡大する。凡例に (x N) として出る（ADR-0028）

sigma = envelope["input"]["broadening"]["sigma"]          # cm^-1
peak = 1.0 / (sigma * math.sqrt(2.0 * math.pi))           # ガウス型の L(0)
heights = [line["weight"] * peak * MAGNIFY for line in lines["lines"]]
```

## 上書きの規則

調整の成果はスクリプトの側にしかないので、生成が既存のファイルを黙って潰してはならない。

| 状況 | 振る舞い |
|---|---|
| 生成先がない | 書き出し、`wrote result_plot.py` と知らせる |
| 生成先がある | **書かずに残す**。`kept result_plot.py (--force-script to regenerate)` と知らせる |
| `--force-script` あり | 上書きする |

「ある場合はエラーで止める」ではなく「残して知らせる」にするのは、条件を振りながら
2 をやり直す運用で `run ... --script` が毎回エラーになると使い物にならないからである。
この規則なら `run --script && python result_plot.py` が何度でもそのまま通る。

生成は `--script` を付けたときだけ行う（`--plot` や `--log` と同じ opt-in）。省略時の
生成先は `-o` のファイル名から作る（`result.json` → `result_plot.py`、その中の
`OUTPUT` は `result_plot.png`）。

## 入力ファイルの受け取り方をどうするか

結論から言うと、**入力ファイルの形は変えない**。変わるのは「何を入れないと決めたか」の
方で、これを明文化する。

### 入れないもの

図の設定は入力ファイルに入れない。理由は冒頭に書いたとおりだが、もう 1 つある。
入力ファイルは結果 JSON に**正準形でエコーされる**（ADR-0010）。図の設定をそこに混ぜると、
「計算をやり直していないのに結果ファイルの中身が変わる」ことが起きる。`load → save` で
ファイルが変化しない性質（ADR-0008）が、図をいじるたびに揺さぶられる。

### すでにある対称性

入力ファイルは `modes` に `{"path": "modes.csv"}` を書けば、モード表という**大きくて
外由来のデータ**を外部ファイルへ追い出せる（ADR-0019）。今回やるのはその裏返しで、
**大きくて自由度の高い設定**を外部ファイル（作図スクリプト）へ追い出す。入力ファイルは
両側から挟まれて「計算の条件だけ」に痩せていく。これは ADR-0045（入力ファイルの型と
計算用の値の型を分ける）が引いた線と同じ向きである。

### CLI の上書きはどうなるか

`--temperature` / `--sigma` / `--e-min` / `--e-max` / `--de` / `--min-weight` などは
そのまま残す。どれも**数を変える**つまみで、境界の内側にある（ADR-0012, 0050）。

いっぽう `--title` / `--magnify` / `--dpi` は**絵を変える**つまみである。既存のものは
当座そのまま残すが、規則としてこう決める。

> **図のつまみを CLI に新しく足さない。図を調整したくなったら作図スクリプトを生成する。**

こう決めておけば、要望が来るたびにオプションが増えていく道が最初から塞がる。既存の
3 つを消すかどうかは実装してから決めればよい（後述の未決）。

### 1 ファイル方針は据え置く

「分子のファイル」と「条件のファイル」に割る案は今回も採らない。条件を振る用途は CLI の
上書きで足り、分子を共有する用途は `modes` の外部 CSV で足りる。ADR-0005 の「1 ファイルで
計算が完全に再現できる」性質を割る理由が、今回の話からは出てこない。

### 保留: 実行に名前を付けるか

入力ファイルに `label`（分子名や実験条件の覚え書き）を足し、結果 JSON にエコーして
作図スクリプトの既定の表題に使う案がある。これは絵ではなくデータの属性なので境界には
反しない。ただし「他に何を入れてもよいか」が曖昧になりやすいので、今回は入れない。
表題はスクリプトに直接書けばよい。

## パッケージ側の設計

### 雛形は実物の Python ファイルとして持つ

`src/fcenvelope/templates/{envelope,lines,overlay}.py` に、**そのまま走る Python ファイル**
として置く。生成は「読んで、生成ヘッダのマーカーの間だけ差し替えて、書く」だけにする。
文字列を組み立てて作らない。

- 雛形そのものが lint と型検査の対象になり、壊れたまま配られることがない。
- 図のコードの差分が、生成ロジックの差分ではなく**図のコードの差分**として読める。
- 試験が雛形を直接走らせられる。

パッケージデータとして配る必要があるので、`importlib.resources` で読む。

### 新しいモジュール

| モジュール | 責務 | 依存先 |
|---|---|---|
| `scripts.py` | 雛形の選択と生成ヘッダの差し替え。**matplotlib に依存しない**（テキストを書くだけ） | errors, logs, result |

種類による振り分けは関心ごとの表に置く（ADR-0049）。

| モジュール | 表 |
|---|---|
| `scripts.py` | `TEMPLATES`: 結果の型 → 雛形の名前 |

重ね描きは表に載せず専用の関数のままにする（`plotting.plot_overlay` と同じ扱い）。
`test/test_dispatch.py` に行を 1 つ足し、`RESULT_KINDS` / `DRAWERS` / `REPORTERS` と
同じ種類を網羅していることを見る。

### CLI

```
fcenvelope run   INPUT.json -o RESULT.json [--script [FILE]] [--force-script]
fcenvelope lines INPUT.json -o LINES.json  [--script [FILE]] [--force-script]
fcenvelope script RESULT.json [LINES.json] -o PLOT.py [--force]
```

`script` の引数の形は `plot` と同じにする（1 つなら種類で振り分け、2 つなら重ね描き、
順序は問わない、それ以外は使用法エラー）。生成は節目（ファイルの書き出し）なので
`logs.stage` を通す（ADR-0052）。

### 既定の見た目が 2 か所に分かれる件

`plotting.py` の `plot_envelope` 等（ライブラリ API、ADR-0011）と、雛形の `draw` は、
同じ図を 2 回書くことになる。これは ADR-0036 が消したはずの重複だが、今回は**残して
試験で留める**。`io` と `inputs` が `schema_version` を別々に持ち、一致をテストで
確かめているのと同じ扱いにする。

雛形を module として import し、`draw(ax, data)` を呼んだ軸と `plot_envelope(result)` の
軸を比べる（軸ラベル・線の頂点列・ガイド線）。雛形が `draw` を持つ形にしてあるのは、
この試験と、notebook から使えることの両方のためである。

片方に寄せる案は 2 つあるが、どちらも今は採らない。

- **`plotting.py` を消して雛形に寄せる**: ライブラリ API の約束（ADR-0011）を壊す。
- **雛形が `fcenvelope` を import する**: 図の設定が `plot_envelope` の中に隠れ、
  「スクリプトを読めば全部分かる」という今回の目的そのものを失う。

### 試験

| 何を見るか |
|---|
| 生成したスクリプトが subprocess で走り、画像が出る（種類 3 つとも） |
| 生成したスクリプトが `fcenvelope` を import していない |
| 生成先が既にあるとき上書きしない。`--force` で上書きする |
| 生成ヘッダの差し替えが、マーカーの外を変えない |
| 既定の `draw` と `plotting` の描画が一致する |
| `TEMPLATES` が他の表と同じ種類を網羅している（`test_dispatch.py`） |
| 画像に焼いたメタ情報が読み出せる |

## 検討した選択肢

- **2 にフックして直接図を出す**: 今の `--plot` がこれで、残しはするが調整の道には
  しない。重い計算をやり直さないと図が変わらないのでは 3 段に分けた意味がない。
- **CLI のオプションを増やす**: matplotlib の API を写し続けることになり、しかも設定が
  実行後に残らない。今回の目的の半分（残ること）を最初から満たせない。
- **入力 JSON に `plot` セクション**: 同じ写像を pydantic で行うことになる。加えて結果の
  入力エコーが図の設定で揺れる（ADR-0008, 0010）。
- **gnuplot の雛形も同時に出す**: 採りたいが、gnuplot は JSON を読めないので**列指向の
  データ書き出し**が要る。これは「CSV / NPZ 等の追加出力形式は設けない」と決めた
  ADR-0010 を開き直すことになるので、matplotlib の雛形が固まってから別に判断する。
  `TEMPLATES` の表と `--script` の生成先の拡張子で振り分ける形にしておけば、後から
  足せる（`.py` → matplotlib、`.gp` → gnuplot）。
- **1 つの入力からエンベロープと線をまとめて計算し、重ね描きの雛形まで一度に出す**:
  重ね描きの生成が 1 手で済むが、線の列挙はモード数に対して組合せ的に重くなりうるので、
  エンベロープだけが欲しい実行に抱き合わせられない。`run` と `lines` は分けたままにする。
- **`plot` サブコマンドを廃して `script` に置き換える**: 描画の実装が 1 つになるので
  筋は通る。ただし「とりあえず一目見る」経路は残す価値があるので、今回は両方残して
  試験で縛る。使われ方を見てから決めればよい。

## 受理したら起こす ADR

| 番号（仮） | 決めること |
|---|---|
| 0057 | 図の設定は生成した作図スクリプトに置き、入力ファイルにも CLI にも置かない |
| 0058 | 作図スクリプトは単独で動き、結果ファイルを実行時に読む |

## 決めていないこと

1. `--script` を既定で on にするか。今は opt-in を提案している（`--plot` / `--log` と
   揃える）。運用してみて毎回付けるようなら既定にしてよい。
2. `plot` サブコマンドと `--title` / `--magnify` / `--dpi` を最終的に残すか。
3. モジュール名を `scripts.py` にするか（`plotscript.py` / `emit.py` も候補）。
   パッケージデータのディレクトリ名 `templates/` と衝突しない名前であること。
4. gnuplot をいつ入れるか。入れるなら列指向のデータ書き出しを先に決める（ADR-0010）。
5. 生成された画像の既定名（`result_plot.png`）。`result.png` の方がよければ、
   末尾の `_plot` を落とす規則にする。
