# `diagonalize` サブコマンド 作業計画

非対角項を含む基底で振動数と結合を与える入力形式を足す。決定は ADR-0037 に、語彙は
`CONTEXT.md` に、現行の仕様は `docs/dev/spec/interface.md` にある。

抽象化リファクタリング（ADR-0031〜0043）はこの作業を残して完了している。`units.py` /
`models.py` / `physics.py` / `envelope.py` / `lines.py` の層分けはすでに入っており、
ここで足すのは `normalmodes.py` とサブコマンド 1 つだけである。

## 前提

- **対角化はパーサの中で行わない。** `fcenvelope diagonalize` という別コマンドとし、その
  出力である modes CSV を既存の `{"path": ...}` 参照（ADR-0019）で読む。
- 理由は、対角化が「入力の解釈」ではなく**別の計算**だからである。単位変換や流儀変換は
  情報を失わない可逆な写像だが、対角化は数値計算であり、失敗しうるし（負の固有値＝虚振動を
  どう扱うか）、診断値を持つべきものである。これを pydantic の validator に押し込むと、
  「入力のパースに失敗した」のか「対角化が物理的に破綻した」のかが例外の型で区別できなくなる。
- 出力は現行のモード表 CSV とし、`modes` の参照形態は増やさない。

## 作業

1. `normalmodes.py` を足す。層は `models` の上、`physics` の隣（ADR-0041 の図を参照）。
2. `fcenvelope diagonalize` サブコマンドを足す。出力は `frequency,coupling` の 2 列 CSV。
3. **並進・回転の 6 自由度を落とす閾値は既定値を置かず引数で明示必須にする。**
   低振動数モードは熱占有が大きく（300 K で 15 cm⁻¹ なら n ≈ 13.4、1200 cm⁻¹ なら
   n ≈ 0.003）、境界付近の 1 本を入れるか落とすかでエンベロープの幅が目に見えて変わる。
   `temperature` に既定値を置かなかったのと同じ扱いにする（ADR-0021）。
4. 虚振動は `frequency > 0` の制約により黙って通り抜けられない。縮退は同値の行として見える。
   質量重みの規約は無次元の S に変換された時点で消費される。

## 検証

`uv run pytest`。対角化した結果を既知の対角系と突き合わせる（対角行列を入れたら
固有値がそのまま出る、回転させても S が不変、など）。
