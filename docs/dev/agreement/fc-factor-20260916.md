## 1. 背景と目的

- 既存の `compute_envelope` は時間相関関数のフーリエ変換によりスペクトル全体を高精度に与えるが、「どの振動モードが何量子ぶん効いているか」という個々の遷移の情報は積分に溶けて見えなくなる。
- `docs/theory/fc-factor.md` の言う通り、定性的な考察では**主要な離散 FC 因子だけを取り出す**ことに意義がある。
- したがって v1 に、FC 因子とその遷移エネルギーの組を列挙する系統を追加する。エンベロープを置き換えるものではなく、同じ物理量の別表現として並置する。

## 2. 計算する量

### 2.1 FC 因子

理論文書の漸化式をそのまま実装する。平行移動演算子 $U(g)=\exp(g(a^\dagger-a))$ について

$$
\sqrt{n+1}\braket{m|U|n+1}=\sqrt{m}\braket{m-1|U|n}-g\braket{m|U|n},
\qquad
\braket{m|U|0}=e^{-g^2/2}\frac{g^m}{\sqrt{m!}}
$$

で行列要素を組み、$\mathrm{FC}_{mn}=|\braket{m|U|n}|^2$ とする。

- 引数は正準量 $S$ で受ける。$g=\sqrt S$ であり、$g$ の符号は FC 因子に効かない（`io-and-class-design-20260725.md` §2.2）。
- 初期条件の $g^m/\sqrt{m!}$ は対数で組み立て、$m$ が大きい領域の桁溢れを避ける。

### 2.2 遷移エネルギー

**符号規約はエンベロープと同一で、反転しない**（同 §3）。$E=0$ が ZPL であり、

$$
E = -\sum_\alpha (m_\alpha - n_\alpha)\varepsilon_\alpha
$$

振動量子を正味 $k$ 個生成する線は $E=-k\varepsilon_\alpha$（負側）に、ホットバンドは正側に立つ。

### 2.3 線強度

FC 因子そのものに加え、始状態の熱占有 $P(n_\alpha)=(1-x_\alpha)x_\alpha^{n_\alpha}$, $x_\alpha=e^{-\varepsilon_\alpha/k_BT}$ を掛けた**線強度**

$$
I = \prod_\alpha P(n_\alpha)\,\mathrm{FC}_{m_\alpha n_\alpha}
$$

を併せて持つ。$T=0$ では $P(0)=1$ なので $I=\mathrm{FC}$ に一致する。

$I$ を導入する理由は、これが**エンベロープと直接突き合わせられる量**だからである。線を中心 $E$・標準偏差 $\sigma$ のガウシアンで畳んで足し上げたものは `compute_envelope` の $F(E)$ に一致する。これは $\rho(\tau)$ の母関数展開そのもので、$T=0$・単一モードでは同 §3 のポアソン級数に帰着する。系として

$$
\sum_{\text{全遷移}} I = 1
$$

が厳密に成り立ち、実装検証の軸になる（§6）。FC 因子だけでは温度が入らないため、この対応が作れない。

### 2.4 縮退した線をまとめない

エネルギーが偶然一致する遷移（別モードの組み合わせ、$S=0$ での $n\to n$ など）は、別々の線として残す。まとめると量子数のラベルが失われ、「どのモードが効いているか」という本機能の目的が損なわれるため。

## 3. 何を返すか — 閾値による打ち切り

全遷移は無限個あるので、返す線を選ぶ基準が要る。**線強度の絶対閾値 `min_intensity` を唯一の主たるつまみ**とし、これ以上の線をすべて返す。

### 3.1 閾値による枝刈りが網羅的である理由

1 モードあたりの寄与 $P(n)\mathrm{FC}_{mn}$ は 1 以下なので、完成した線の強度は途中経過の積を超えない。したがってモードを 1 つずつ合成しながら閾値で枝刈りしても、閾値以上の線を取りこぼさない。さらに未処理のモードが到達しうる重みの積の上限を掛けて枝刈りすることで（$\text{suffix\_bound}$）、途中経過の本数を抑えたまま網羅性を保つ。

モードごとの選択は独立なので $\text{suffix\_bound}[0]$ は**最強の線の強度そのもの**になる。閾値が高すぎて 1 本も残らない場合はこの値を警告文に載せ、どこまで下げればよいかを示す。

### 3.2 相対閾値を採らない判断

「最強の線の何分の 1 まで」という相対指定も検討したが採らない。絶対閾値なら `captured_intensity`（拾えた強度の総和）がそのまま「スペクトルのどれだけを見ているか」を意味し、エンベロープとの突き合わせにも直結する。つまみを 2 つ持つより、1 つの意味が明確なつまみと、上記の警告文で十分と判断した。

### 3.3 補助的な上限

- `max_lines`: 保持・列挙する線数の上限。超えた場合は強度上位のみを残し、`beam_truncated` を立てて警告する（このとき網羅性は保証されない）。
- `max_quanta`: 1 モードあたりの振動量子数の上限。省略時は打ち切り残差が `min_intensity` を下回るまで自動で伸ばす。

### 3.4 多モード系での限界

熱的に活性なモードが多いと、強度が膨大な数の線に分散して 1 本も閾値に届かなくなる。これは実装の不足ではなく、離散線による記述がその系で意味を失っているということであり、理論文書が「スペクトル全体にはフーリエ変換が重要」と言う所以でもある。空の結果と最強の線の強度を返し、警告でそう伝える。

## 4. 数値品質の診断

エンベロープと同じ方針を採る。**計算は常に完走させ、品質は診断値として記録し、閾値を超えたものは `NumericalQualityWarning` で発報しつつ同じ文言を `messages` に残す。**

| 診断値 | 検出する問題 | 閾値の目安 |
|---|---|---|
| `captured_intensity` | 閾値が粗く、スペクトルの大半を取りこぼしている | < 0.9 で警告。線が 0 本なら最強の線の強度を添えて警告 |
| `beam_truncated` | `max_lines` で列挙を打ち切った。網羅性が失われている | True で警告 |
| `min_mode_completeness` | 振動梯子の打ち切り（$\sum_m \mathrm{FC}_{mn}=1$ からのずれ） | 1 からのずれが `min_intensity` 以上で警告 |
| `recurrence_limited` | 漸化式の数値的破綻を避けて始状態を打ち切った | True で警告 |
| `mean_energy` | $\langle E\rangle=-\lambda$（同 §11 の 1 次モーメント）からのずれ。収束の目安 | 警告なし（記録のみ） |
| `n_lines` / `max_initial_quanta` / `max_final_quanta` | 列挙の規模 | 警告なし（記録のみ） |

### 4.1 漸化式の破綻とその検出

$g$ が大きく $n$ も大きい領域では $\sqrt{m}\braket{m-1|U|n}$ と $g\braket{m|U|n}$ が桁落ちし、漸化式が破綻する（例: $S=25$ では $n\simeq 20$ 付近から）。

2 つの打ち切りを**列和 $\sum_m \mathrm{FC}_{mn}$ の向き**で見分ける。$\mathrm{FC}_{mn}$ は非負なので、

- **$m$ の打ち切り**（梯子が短い）は正の項を落とすだけなので列和は 1 を**下回る** → `m_max` を倍々に伸ばして解消する。
- **数値的破綻**は誤差が二乗されて正の側に積み上がるため列和が 1 を**上回る** → `m_max` を伸ばしても解消しないので、破綻が始まる直前の列までで $n$ を打ち切り、`recurrence_limited` を立てる。

閉じた解析形（Laguerre 陪多項式）に置き換えれば破綻自体は避けられるが、理論文書が「漸化式により求めた行列要素を二乗する」と定めているので実装は漸化式のままとし、破綻は検出して縮退させる方針を採る。解析形はテスト側の参照として使う。

## 5. インターフェイス

### 5.1 公開 API

エンベロープと同じ「計算・保存・読み込み・描画」の自由関数 4 つを並置する。結果クラスは引き続き純粋なデータ容器。

```python
compute_fc_lines(
    modes: Sequence[VibrationalMode],
    *,
    temperature: float,
    min_intensity: float = 1e-4,
    max_lines: int = 10000,
    max_quanta: int | None = None,
) -> FCLinesResult

save_fc_lines(result: FCLinesResult, path: str | Path) -> None
load_fc_lines(path: str | Path) -> FCLinesResult
plot_fc_lines(result, *, ax=None, label=None, title=None) -> matplotlib.figure.Figure
```

加えて、理論文書の式そのものを直接使えるよう `fc_factor_matrix(huang_rhys, m_max, n_max=0)` を公開する。

- `temperature` はキーワード必須。既定値を置かず、どの温度で計算したかが呼び出し側に必ず現れるようにする。
- `Conditions` は受け取らない。離散線に `sigma` / E グリッドは要らず、必要なのは `temperature` だけだからである。CLI 側が `conditions.temperature` を渡す。

### 5.2 データモデル

```python
@dataclass(frozen=True, slots=True)
class ModeTransition:
    mode_index: int; initial: int; final: int      # n_alpha -> m_alpha

@dataclass(frozen=True, slots=True)
class FCLine:
    energy: float                                  # -sum (m-n) eps [cm^-1]
    fc_factor: float                               # prod FC_mn
    intensity: float                               # prod P(n) FC_mn
    transitions: tuple[ModeTransition, ...]        # n = m = 0 のモードは含めない

@dataclass(frozen=True, slots=True)
class FCLineDiagnostics: ...                       # §4 の表
@dataclass(frozen=True, slots=True)
class FCLinesResult: ...                           # lines / 入力エコー / 診断値 / 来歴
```

`transitions` から $n_\alpha=m_\alpha=0$ のモードを省くのは、200 モード系で 1 本の線に 200 個の 0 を持たせないため。空タプルは ZPL を意味する。`FCLinesResult` は `energies` / `fc_factors` / `intensities` を ndarray として返すプロパティを持つ。

線は**強度の降順**（同強度ならエネルギーの昇順）に並べる。「主要なもののみに絞る」という目的からは順位そのものが情報だからである。

### 5.3 出力ファイル

エンベロープと同じ単一 JSON。`kind` で系統を区別する。

```json
{
  "schema_version": 1,
  "kind": "fcenvelope.fc_lines",
  "fcenvelope_version": "0.1.0",
  "created_at": "2026-09-16T01:23:45Z",
  "energy_unit": "cm^-1",
  "input": {
    "frequency_unit": "cm^-1",
    "coupling_convention": "huang_rhys",
    "modes": [{ "frequency": 1200.0, "coupling": 0.25 }],
    "temperature": 300.0
  },
  "selection": { "min_intensity": 0.0001, "max_lines": 10000 },
  "derived": { "reorganization_energy": 300.0 },
  "diagnostics": { "n_lines": 58, "captured_intensity": 0.997, "...": "..." },
  "lines": [
    { "energy": 0.0, "fc_factor": 0.41, "intensity": 0.36, "transitions": [] },
    { "energy": -450.0, "fc_factor": 0.26, "intensity": 0.23,
      "transitions": [{ "mode": 1, "initial": 0, "final": 1 }] }
  ]
}
```

- 入力エコーは引き続き正準形（`coupling_convention` = `"huang_rhys"`）で書き出し、それ以外は読み込み時に reject する。
- `conditions` ではなく `temperature` だけを持つ。持たない値をエコーすると、再現できない情報を持っているように見えるため。
- `schema_version` は 1 のまま。既存の入力・出力に手を触れない純粋な追加のため。

### 5.4 CLI

```
fcenvelope lines INPUT.json -o LINES.json [--plot FIG.png] [--dpi INT]
                 [--temperature FLOAT] [--min-intensity FLOAT]
                 [--max-lines INT] [--max-quanta INT] [--show INT]
```

- 入力 JSON は `run` と同一のものをそのまま使う。`conditions` のうち `temperature` だけを読み、`sigma` / E グリッドは無視する。上書きできるのも `--temperature` のみ。
- `--show`（既定 10）は強度上位の線を標準出力に表を出す。定性的な考察が目的なので、ファイルを開かずに主要な遷移が読めることを重視する。
- `fcenvelope plot` は `kind` を見てエンベロープと棒スペクトルのどちらかを描く。利用者が結果ファイルの種類を意識せずに再描画できる。

## 6. テスト方針

引き続き**解析解・恒等式による検証を中核**に据える。

| テスト | 検証する内容 |
|---|---|
| 漸化式 vs Laguerre 陪多項式 | 行列要素そのものの正しさ |
| 列和 $\sum_m \mathrm{FC}_{mn}=1$ | $U$ のユニタリ性 |
| $\mathrm{FC}_{mn}=\mathrm{FC}_{nm}$ | 漸化式とは独立な不変量 |
| $n=0$ 列 $=e^{-S}S^m/m!$ | ポアソン級数（同 §3 の検算式） |
| **線をガウシアンで畳む = エンベロープ** | 符号規約・熱占有・規格化の全部。独立な 2 実装の突き合わせ |
| $\sum I \to 1$、$\langle E\rangle\to-\lambda$ | 0 次・1 次モーメント（同 §11） |
| 粗い閾値の結果 ⊂ 細かい閾値の結果 | 枝刈りの網羅性（§3.1） |
| 列和が 1 を上回る / 下回る | 破綻と梯子打ち切りの向きの違い（§4.1） |

## 7. 明示的なスコープ外

- 縮退した線のマージ（§2.4）。
- 相対閾値、および強度上位 N 本だけを取る指定（`max_lines` は上限であって順位指定ではない）。
- 線のエネルギー窓による絞り込み。順位で絞るのが本機能の趣旨であり、窓が要るなら呼び出し側で濾せる。
- CSV / NPZ 等の追加出力形式（`io-and-class-design-20260725.md` §13 を踏襲）。
- 吸収／発光の区別、Duschinsky 回転、非調和性など（同 §13 をそのまま踏襲）。
