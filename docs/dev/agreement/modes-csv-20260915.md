## 1. 背景

- モードは「同じキーを持つレコードが並ぶ表」であり、外部の量子化学計算から機械的に生成されることが多い。
- 表形式データの共通語は CSV で、awk / Excel / pandas などどこからでも作れる。
- 検討した書き方: records（現行）、列指向（キーごとの配列）、ヘッダ＋行、外部ファイル参照。
  - 列指向は §4.1 で避けた「長さ不一致」のバグを復活させるため不採用。
  - ヘッダ＋行は列位置依存で、列の追加に弱いため不採用。
- **records（JSON 内に直接書く）＋ CSV 参照** を基本とする。

## 2. 決定事項

### 2.1 参照の書き方

`modes` には従来の配列に加え、CSV への参照オブジェクトを置ける。

```json
{
  "schema_version": 1,
  "frequency_unit": "cm^-1",
  "coupling_convention": "g",
  "modes": { "path": "modes.csv" },
  "conditions": { "...": "..." }
}
```

- 参照オブジェクトのキーは `path` のみ。未知キーはエラー（区切り文字指定などは将来の拡張余地として空けておく）。
- 相対パスは**入力 JSON ファイルのディレクトリ**を基準に解決する（カレントディレクトリではない）。`from_obj` / `from_json` では `base_dir` 引数で基準を与え、省略時はカレントディレクトリ。
- `frequency_unit` / `coupling_convention` は JSON 側のトップレベルが引き続き担う。CSV は数値の表だけを持つ。
- 参照はパース時に解決し、パース後の `FCEnvelopeInput.modes` は配列で書いた場合と区別がない。
- `schema_version` は 1 のまま（従来の入力はすべてそのまま有効な上位互換の追加のため）。

### 2.2 CSV の書式

```csv
frequency,coupling
1200.0,0.5
450.0,0.8
```

- **RFC 4180 に準拠する**（CSV の書式・ヘッダの扱いは独自拡張しない）。
  - 区切りはカンマ、引用符付きフィールド（`"1200.0"`）可、改行は CRLF / LF のどちらも可、最終行末の改行は任意。
  - フィールド前後の空白は RFC 4180 に従いフィールドの一部として扱う。したがって `frequency, coupling` はヘッダと認識されず、データ行として数値変換に失敗しエラーになる。数値フィールド中の空白の解釈は値の変換（pydantic）に委ねる。
  - RFC 4180 にはコメントの規定がないため、コメント行は受け付けない（`#` で始まる行も通常のレコード）。W3C の CSV on the Web は `commentPrefix` を持つが、これはメタデータ側で方言を宣言する仕組みであり CSV 自体の仕様ではないので採らない。
  - 空行は「空のレコード」であり列数不一致としてエラーにする。
  - 文字コードは UTF-8。BOM は文字コード層の問題として許容する（Excel 出力対策）。
- 列は **`frequency` と `coupling` の 2 列のみ**。それ以外の列があればエラー。
- ヘッダは RFC 4180 と同じく**省略可**。
  - RFC 4180 はヘッダの有無を MIME パラメータ（`header=present|absent`）で外から伝えるが、ファイル単体では使えない。そこで 1 行目の内容で判定する。
  - 1 行目がちょうど `frequency` と `coupling` の組（順序は問わない）ならヘッダ。そうでなければ `frequency, coupling` の順のデータ行とみなす。
  - 列名は数値にならないので、ヘッダとデータ行を取り違えることはない。2 列なので、ヘッダ無しでも列順の取り違えは起きにくいと判断した。
  - 1 行目がヘッダでもデータ行でもない場合（列名の誤記、余分な列など）は、1 行目のエラーに「ヘッダを書くならこの 2 列ちょうど」という案内を添える。
  - `index` や `label` などの補助列は、読み飛ばすと「意味のある列」と誤解されやすく、しかも何も検証されないため受け付けない。必要になった時点で、意味と検証（一意性など）を決めて追加する。
  - 行の重複は検出しない。縮重モードは振動数・coupling とも同値の行が正当に複数並ぶため。行の順序は計算結果に影響しない。
- 次はエラー（`InvalidInputError`、`ファイル名:行番号` 付き）: CSV として不正（引用符の崩れなど）、列数の不一致（余分な列、空行・コメント行を含む）、ヘッダの誤記（1 行目の数値変換失敗として検出）、数値でない値、値の範囲違反（§4.2 と同じ制約）、データ行が 0 件。

### 2.3 「1 ファイルで再現」の扱い

§4.1 の「1 ファイルに全部」は、入力側では CSV 参照により崩れる。再現性は**結果 JSON が担う**：結果の入力エコーは常に正準形のモード配列を埋め込むため、結果ファイル単体から計算を再現できる。

### 2.4 CLI

- 新しいオプションは追加しない。CSV は入力 JSON から参照する。
- 「`modes` は CLI で上書きしない」（§9.1）は維持する。

## 3. スコープ外

- タブ区切り・空白区切り、区切り文字の指定
- コメント行
- `index` / `label` / `symmetry` などの補助列
- 列名のマッピング（`freq` → `frequency` など）
- CSV 側での単位・流儀の指定
- `modes` の CLI からの差し替え（`--modes`）
