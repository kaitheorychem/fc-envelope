# エンベロープと離散 FC 因子の重ね描き

- 日付: 2026-09-16
- 種別: **イミュータブル**（原則更新せず、変更時は新文書を追加）
- 位置づけ: `fc-factor-20260916.md` で並置した 2 つの表現（エンベロープ F(E) と離散 FC 因子）を 1 枚の図に重ねるための追加合意。計算そのものには手を入れない、描画だけの決定。

> [!IMPORTANT]
> **この文書は仕様書ではない。**
> ここに書かれているのは「ある時点で交わした検討・合意」であり、現在のシステム仕様を反映するものではない。
> 実装が進めば現実のコードとは食い違っていく前提で読むこと。

## 1. 背景と目的

- `run` と `lines` は同じ物理量の別表現であり、横軸 E の規約も範囲も共通している（`fc-factor-20260916.md` §2.2）。
- 両者を別々の図で見ると「エンベロープのこの肩はどの遷移か」が目で追えない。曲線と棒は描かれ方が違うので、1 枚に重ねても互いを潰さない。
- したがって、2 つの結果クラスを受け取って 1 枚に重ねる描画関数を足す。

## 2. 縦軸をどう揃えるか — 本文書の中心的な判断

2 つの量は次元が違う。F(E) は 1/cm⁻¹、線強度 I は無次元である。素朴には縦軸を左右 2 本立てる（`twinx`）ことになるが、**これは採らない**。2 本の軸の高さの対応づけが恣意的になり、「この棒はエンベロープのピークと同じ高さだ」という、データにない対応を図が主張してしまうためである。

代わりに**縦軸を 1 本に保ち、棒の側を F(E) の単位へ変換する**。変換係数は恣意的な定数ではなく理論から決まる。`fc-factor-20260916.md` §2.3 の通り、F(E) は各線を幅 σ の規格化ガウシアンで畳んで足し上げたものである。

$$
F(E) = \sum_\ell I_\ell\, G_\sigma(E - E_\ell),
\qquad
G_\sigma(0) = \frac{1}{\sigma\sqrt{2\pi}}
$$

したがって

$$
h_\ell = I_\ell \cdot G_\sigma(0) = \frac{I_\ell}{\sigma\sqrt{2\pi}}
\quad [1/\mathrm{cm}^{-1}]
$$

は「その線が F(E) に立てる山の高さそのもの」であり、曲線と同じ縦軸に置いて**高さを直接読める**。

この置き方には検算としての意味もある。

- 孤立した線では棒の先端が曲線の山に一致する（隣の線の裾が効かないため）。実装ではこれを許容誤差 1e-9 で検証している。
- σ の中に何本も密集するところでは曲線が棒より高くなる。これはスケールの都合ではなく「1 本では説明がつかない、重なりで出来た山だ」という事実の表示である。

σ は `envelope` 側の `conditions` から取る。`FCLinesResult` は σ を持たない（離散線に σ は要らない）ので、重ね描きは必ずエンベロープの条件に従う。

## 3. 密集系のための倍率

モードが多い系や高温では線が σ の中に埋もれ、棒が軸の底に潰れて構造が読めなくなる。このため棒だけを拡大する `magnify` を持つ。ただし**倍率は凡例に `(×N)` として必ず出す**。分光のスペクトル図で拡大部に倍率を添えるのと同じ作法で、§2 で担保した「高さが読める」性質を、拡大したことを隠さない形で保つ。既定は 1.0（無変換）で、そのときは凡例に何も足さない。

## 4. 横軸の窓

横軸は `envelope` の E 窓（`e_min` / `e_max` から決まる出力グリッドの両端）に合わせる。窓は利用者が明示的に選んだ範囲であり、図の枠として正しい。一方 `lines` は窓を持たず `min_intensity` 以上を全部返すので、窓の外に立つ線はありうる。**黙って落とさず、CLI が落とした本数を警告に出す。**

## 5. 突き合わせの前提が崩れていたら警告する

§2 の対応が成り立つのは、2 つの結果が同じモード・同じ温度で計算されている場合に限る。食い違っていれば描く前に `UserWarning` を出す（モードの不一致を優先して報告する）。描画自体は止めない。意図的に別条件を並べたい場合もあるし、計算を完走させて品質は警告で知らせるという既存の方針（`io-and-class-design-20260725.md`）に合わせる。

## 6. API と CLI

```python
plot_overlay(envelope: FCEnvelopeResult, lines: FCLinesResult, *, ax=None,
             envelope_label="envelope", lines_label="FC lines",
             magnify=1.0, title=None) -> matplotlib.figure.Figure
```

既存の描画関数と同じ作法に揃える。`Figure` を返すのみで保存はしない。`ax` を受けるので、他の図の一部として組み込める。

CLI は新しいサブコマンドを足さず、既存の `plot` に 2 つ目のファイルを取らせる。

```
fcenvelope plot RESULT.json LINES.json -o FIG.png [--magnify FLOAT]
```

- `plot` はもともと `kind` を見て描き分けるので、種類の判定はすでにある。同じ仕組みで 2 ファイルの役割も決まり、**与える順序は問わない**。
- エンベロープ 1 つと線リスト 1 つ以外の組み合わせ（同種 2 つ、3 つ以上）は使用法エラー（終了コード 2）とする。
- `run` / `lines` の `--plot` は単独の図のままにする。重ね描きには両方の結果が要るので、結果を書き出したあとの合成として `plot` に置くほうが筋が通る。

## 7. 色

エンベロープと棒に既定のサイクル色を共有させると同色になるので、重ね描きのときだけ明示的に割り当てる（`ENVELOPE_COLOR` / `LINES_COLOR`）。単独の描画関数は既定色のまま（`ax` を渡して複数条件を重ねたときにサイクルが効く）とし、挙動を変えない。
