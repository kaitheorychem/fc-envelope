# ゴールデンケースの足し方

外部の類似プログラムの出力と本プログラムの計算を突き合わせるテストである。形式をそう
決めた理由は [ADR-0082](../adr/0082-golden-cases-compare-with-external-programs.md) にある。
ここに書くのは置き場所と書き方と手順だけである。見本は
[test/golden/analytic-single-mode-t0/](../../test/golden/analytic-single-mode-t0/)（解析解を
参照データにしたケース）。

## 置き場所

1 ケースが `test/golden/` の下のディレクトリ 1 つである。ディレクトリ名がテストの名前に
なるので、系と条件が分かる名前にする（例: `pyrazine-4modes-300k`）。

```
test/golden/<ケース名>/
  case.toml       出どころ・比べる表現・許容差・CSV の列
  input.toml      本プログラムの入力ファイル（参照データと同じ条件）
  envelope.csv    エンベロープの参照データ（比べるときだけ）
  lines.csv       線の参照データ（比べるときだけ）
```

CSV の名前は `case.toml` に書くので自由だが、特に理由がなければ上の名前にする。

## input.toml

普通の入力ファイルである（[usage.md](../readme/usage.md)）。外部プログラムに与えたのと同じ
モード・温度を書く。

- エンベロープを比べるなら `[broadening]` と `[grid]` が要る。σ は外部プログラムと同じ
  ガウス幅にし、出力窓（`e_min` / `e_max`）は参照データの点をすべて含むように取る。
- 線を比べるなら `[selection]` を書く。`min_weight` は `case.toml` の `[lines].tolerance`
  以下にする（打ち切った線は重み 0 として比べられるため）。
- 計算で品質警告が出るとテストは失敗する。警告の案内どおりにつまみを動かす。

`uv run fcenvelope run test/golden/<ケース名>/input.toml -o /tmp/check.json` のように、
CLI でそのまま計算して確かめられる。

## case.toml

```toml
[source]
program = "<外部プログラム名>"          # 必須
version = "<版>"                        # 任意
note = """
<どの計算の出力か、どう整形したか>
"""                                     # 任意

[envelope]                              # エンベロープを比べるとき
csv = { path = "envelope.csv", columns = [["energy", "eV"], "density"] }
tolerance = 1e-3

[lines]                                 # 線を比べるとき
csv = { path = "lines.csv", columns = [["energy", "cm^-1"], "weight"] }
energy_tolerance = [0.01, "cm^-1"]
tolerance = 1e-4
```

`[envelope]` と `[lines]` は少なくとも一方を書く。知らないキーは誤りになる。

| キー | 意味 |
|---|---|
| `csv.path` | 参照データの CSV。相対パスはケースのディレクトリ基準 |
| `csv.columns` | 列の並びと単位。入力ファイルの `modes.csv.columns` と同じ書き方（下記） |
| `envelope.tolerance` | 面積 1 に正規化した後の、差の絶対値の最大 ÷ 参照の最大値の上限 |
| `lines.energy_tolerance` | 同じ線とみなすエネルギーの差。素の数値なら cm⁻¹、`[値, "単位"]` も書ける |
| `lines.tolerance` | 重みの差の絶対値の上限 |

## 参照データの CSV

書き方は入力ファイルのモード表の CSV と同じである（RFC 4180、コメント行・空行・補助列は
不可、ヘッダは省略可）。

- エンベロープの列は `energy` と `density`、線の列は `energy` と `weight` の 2 つだけ。
- `energy` には `columns` で単位を添えられる（`["energy", "eV"]`、`["energy", 1e-3, "eV"]`、
  `["energy", "a.u."]` など、入力で使える単位すべて）。添えなければ cm⁻¹。
- `density` と `weight` には単位を添えない。
- `columns` を省くと、ヘッダがあればその並び、無ければ `energy` が先。`columns` とヘッダの
  両方があって並びが違えば誤り。
- 行の順番は問わない（エネルギーで並べ替えてから比べる）。エンベロープではエネルギーが
  重複してはならない。

### 整形で直すこと

外部プログラムの出力を、次の決まりに合わせてから入れる。

- **エネルギーの原点と向き。** ZPL が 0 で、振動量子を生成するサイドバンドが**負側**
  （E = −k·ε）。吸収の向き（サイドバンドが正側）なら符号を反転し、絶対エネルギー（光子
  エネルギーなど）なら 0-0 遷移のエネルギーを引く。
- **エンベロープの縦軸。** 大きさ（任意単位か、規格化済みか）は問わない。ただし吸収の ω や
  発光の ω³ のような周波数の因子が掛かっていれば外し、FC の線形状そのものにする。
- **線の重み。** FC 因子に始状態の熱占有を掛けた、全遷移の和が 1 になる数にする。T = 0 なら
  FC 因子そのものである。最大の線を 1 にした相対強度などの場合は、その倍率を戻す。
  縮退した線は 1 行にまとめても分けてもよい（エネルギーでまとめて和を比べる）。

## 比べ方

- エンベロープ: 計算結果を参照の点へ線形補間し、両方を参照の点の上で面積 1 に正規化して
  比べる。参照の点が粗いと補間と正規化の誤差がそのまま載るので、`tolerance` はそれを
  見込んで決める。
- 線: 参照と計算の線を合わせてエネルギー順に並べ、隣との差が `energy_tolerance` 以下のもの
  を 1 本にまとめる。まとめた線ごとに参照と計算の重みの和を比べ、片方に無ければ 0 とする。

## 手順

1. `test/golden/<ケース名>/` を作り、`input.toml`・`case.toml`・CSV を置く。
2. `uv run pytest test/test_golden.py -k <ケース名>` で確かめる。失敗の報告には、最もずれた
   エネルギーと参照・計算の値が出る。
3. 通らないときは、まず整形（原点・向き・周波数の因子・重みの倍率）と条件（σ、温度、
   モード）を疑う。本プログラムの側の不具合だと分かったら、許容差を緩めずに直す。
